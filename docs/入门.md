# 新手入门：这台机器在替你做什么决定

这份文档不讲代码结构，只讲三件事：**它每天在算什么、你要怎么操作、它的结论哪里不能信**。
所有数字都是从 `config.yaml`、`evidence/` 或某条命令的输出里抄出来的，改代码的人如果忘了改
这里，请以命令的实际输出为准。参数表、成本口径、实测数字的完整版在 `Quantlab/README.md`；
模型本身（特征、超参、逐折 RankIC、分数分布、特征重要性）在 `docs/model-LightGBM.md`；
仓位规则的细节在 `docs/entry-位置管理.md`。

---

## 1. 它在做的一件实事

一句话：**每天收盘后，这台机器从 1000 只 A 股里挑出它认为未来 5 天最强的那几只，算出每一只
该买多少钱、手里的哪些该卖，写成一个指令文件让你自己核对手动下单。它不会自动下单。**

链条上有四个角色，每个只干一件事：

| 角色 | 干什么 | 不干什么 |
|---|---|---|
| 数据 | 抓行情、按固定名单补齐 1000 只股票的历史日线 | 不判断好坏 |
| 模型（LightGBM） | 给每只股票打一个分 = 预测它未来 5 个交易日能涨多少 | 不决定买不买，也不决定买多少 |
| 仓位规则 | 分数怎么变成钱：建仓线、补仓台阶、单票上限、总仓位上限 | 不改模型给的分数 |
| 你 | 复核指令、决定下不下单 | —— |

**这条分工是刻意的**：模型只负责"谁更强"，赚钱亏钱的结构（多重仓位、什么时候撤）由人写死的
规则决定。好处是模型哪天不准了，损失被规则挡着一部分；坏处是它经常欠配（见第 5 节坑 1）。

### 1.1 分数是什么单位

分数 = 模型预测的**未来 5 个交易日收益率**。0.0130 就是"预测 5 天涨 1.30%"。

**它不是概率，不是置信度**，也不保证真涨 1.3%。回测里过了建仓线的那 5.1 万个"名字-日"，
模型预测 +2.207%、事后 5 日**实际只兑现 +1.167%**（更严的强线那 2.6 万个观测实际 +1.571%，
`logs/calib_stats.log` §3）。也就是说分数的**大小**普遍虚高，只有**先后**有意义。模型的区分度
还集中在两头、中间几乎全平（分数中位 +0.246%，`logs/calib_stats.log` §1），所以它更像一台
"只在最有把握时才说话"的机器。

### 1.2 模型学的是什么

学的不是"A股怎么涨"，而是一个更窄的问题：

> **同一天上市的 1000 只股票里，哪些未来 5 天会比其他股票强？**

所以分数是**相对**的，0.006 不代表"涨 0.6%"，代表"比同类强 0.6%"。你无法从单只股票的分数
判断大盘会不会跌——那是第 2 个模块（总仓位上限）负责的事。

模型用 **25 个因子**回答这个问题，全部来自 K 线和换手数据。基本面数据（PE/PB/ROE）虽然下载了，
但默认不启用：接口只能取**当前时点**的快照，摊到 2023 年的 K 线上就是作弊（见 §6）。

**训练怎么不作弊**：模型不是一次性用全部历史训练完就完事。它每 6 个月重新训练一次，每次只用
"那一天之前"的数据，去预测接下来 6 个月。所以任何一天的分数都是**样本外**产出（8 折滚动，
全样本外共 854,763 行预测）。回测用的就是这个文件，不是"训练完再跑一遍"。

## 2. 每天你要做的事（一条命令）

```bash
cd /d G:\个人量化\Quantlab
python live/run_daily.py            # 只出指令文件，不下单
```

跑完看两样东西：

1. 终端最后打印的 **目标 X 只 / 仓位 Y% / 本轮上限 Z%**。开跑第一行还会打印
   **仓位策略已启用: 建仓线 … / 清仓线 … / 补仓线 开(绝对线 0.0181)**（关闭时打
   `补仓线 关(只按台阶 Δ)`）—— 想知道今天这一轮按哪条补仓规则算，看这行，别翻 `config.yaml`。
2. 生成的指令文件 `live/output/rebalance_日期.md`：卖出在前、买入在后，每笔带股数、参考价、
   金额，表头还标了哪些股票因为涨跌停被剔除。

**先核对再手动下单。** 这台机器上没有任何自动下单通道（`main.py` 的 `--auto-live-trade` 参数
存在，但函数体第一行就 `return`，不会下单）。

其余命令（全历史回测、重训、审计脚本）见 `Quantlab/README.md` 的「命令参考」。
双击 `启动.bat` 有同样的菜单。

跑 `python main.py backtest`，打印长这样（这是 2026-09-27 采纳补仓绝对线之后的实际输出，
`logs/main_backtest.log`）：

```

夏普比率: 1.87          最大回撤: 19.95%       Calmar比率: 1.84
胜率(日): 46.67%        信息比率: 1.15         基准收益: 12.18%   超额: 188.74%
总交易次数: 298          交易总成本: 59,221 元   交易胜率: 47.74%  利润因子: 2.86
平均目标仓位: 36.1%      平均持仓 4.0 只         中位持有交易日: 21（p90 44）
买入被挡 1 笔（开盘涨停）  卖出被挡 0 笔          欠配调仓 41 次，该些次平均滞留现金 1,303,985 元

```

**这些全是费后数字**：佣金万三（最低 5 元）、印花税（2023-08-28 起万五、之前万十，按成交日
取档）、滑点千一，三项都真金白银从现金里扣过，逐笔复核见 `logs/cost_audit.log`。
口径细节和"免掉某一项费率会怎样"的对照在 `Quantlab/README.md`「交易成本口径」。

| 名词 | 白话 | 现在的值 | 要注意什么 |
|---|---|---|---|
| 累计收益率 | 100 万变成交多少，扣完费 | +200.92% | 只有 3.6 年、一次崩盘都没遇到；股票池还有幸存者偏差（坑 7） |
| 年化 | 换算成每年多少 | 36.75% | 是几何平均，不是"每年都能赚这么多" |
| 夏普 | 每承担一份波动换到多少超额 | 1.87 | **扣了无风险利率 2%**（报告口径）；另一条口径（不扣、按日收益算术年化）在 `logs/h5_arms.log` 打的是 1.78 |
| 最大回撤 | 中途最惨一次从高点亏多少 | 19.95% | 这已经算控制得好的；实盘可能更深 |
| 信息比率 | 跑赢指数的那部分稳不稳 | 1.15 | 对照基准是中证1000 `sh000852` |
| 胜率(日) | 多少比例的交易日在涨 | 46.67% | **低于一半是正常的**，赚钱靠赚得大亏得小 |
| 交易胜率 | 按每笔平仓的已实现盈亏算 | 47.74% | 和"日胜率"是两个数，别混用；低于一半也照样赚钱。清仓线抬到 P84 时它从 53.29% 掉下来，但**每笔卖出的均值反而从 +11,466 元涨到 +13,181 元**（赚钱的笔数变少、每笔赚得更多），逐项拆解见 `docs/entry-位置管理.md` §8-D |
| 利润因子 | 赚的钱是亏的钱的几倍 | 2.86 | 大于 1 才算赚钱 |
| 平均目标仓位 | 平均只把钱用出去多少 | 36.1% | **这套规则的固有特征**，见坑 1 |
| 平均持仓只数 | 平均拿几只 | 4.0 只 | 上限 12 只只是天花板，常态远低于它 |
| 中位持有交易日 | 一半单子拿不过 21 天 | 21 日（p90 44 日） | 月度评估 + "没涨够一档就不动"的结果 |
| 减仓/平仓笔数 | 155 笔卖出里 125 笔按清仓线整只清、13 笔减仓、10 笔等比降杠杆、6 笔减到碎仓改清仓 | 见 `策略动作` 那行 | 卖出不是只有一种原因，读回撤时要分清（`docs/entry-位置管理.md` §8-C） |
| IC 门控 | 模型失效时砍半仓的开关 | 触发 8/45 次 | 触发那几个月把上限压到全期最低 14%；但这一段样本里它单独开着是净负贡献（只开它 +104.4%，比不加暴露层的 +154.7% 还少 50.2pp），是防御闸不是已经赚到钱的开关 |


**看哪个就够了**：给别人讲看夏普 + 最大回撤；自己决定敢不敢上钱，看最大回撤和欠配程度。
日胜率和交易胜率不能混着用——前者是"多少天在涨"，后者是"多少笔在赚"。

## 4. 名词对照（看到不懂的词来这里查）

| 术语 | 白话 |
|---|---|
| **因子** | 从 K 线算出来的指标，模型的输入，共 25 个（动量、波动、量比、换手、RSI、MACD、布林带位置、偏度峰度等） |
| **分数** | 模型的输出 = 预测未来 5 天的相对涨幅。不是概率 |
| **样本外** | 用"那天还没见过"的数据训练出来的模型给那天的分数。回测的可信度全靠这个 |
| **RankIC** | 预测排名和实际排名的相关系数。大于 0 = 蒙对了方向，小于 0 = 反向指标 |
| **建仓线 / 强线 / 清仓线** | 三条分数门槛：过线才买（0.01354）；到强线给满仓（0.01807）；跌破清仓线（0.00875）整个卖掉。三条都不是拍脑袋，是按分数分位点反推的（下一行） |
| **分位点标定（P94 / P97 / P84）** | 不说"分数要到 0.0135"，而说"只买模型排最前 6% 的那批"。P94 = 94% 的股票分数比它低；建仓线 = P94、强线 = P97（最前 3%）、清仓线 = P84（掉出最前 16% 就撤）。换标签或换缓存必须重推（`python research/calib_stats.py`） |
| **有效百分位（线不动、分位在漂）** | 上面那三个 P 是**整份缓存合起来**算出来的**一次性标签**，线上只做"分数 ≥ 阈值"的大小比较，不重算分位。但同一条写死的线，在**每一天**的截面里排第几是会变的：896 个信号日里清仓线 0.00875 中位排 **P87.80**，最松的一天 **P28.97**（2024-02-05）、最紧的一天 **P97.50**（2024-12-20），极差 **68.5pp**。落到只数上更直观：建仓线 0.01354 日均 **57.2** 只过线（就是"最前 6%"的本意），可**单日最多 546 只**（2024-01-19）、**最少 6 只**（2024-12-20）；按月均，最松的 2024-02 是 204.5 只/日、最紧的 2024-12 只有 16.3 只/日，差 **12.5 倍**，规则一个字没改。逐日/逐月/逐折的表，以及"改用最近 6 个月重标要把三条数改成多少"见 `python research/percentile_drift.py` → `logs/percentile_drift.log`。**⚠ 上面那串读数测于 2026-09-30 覆盖前的预测文件**；覆盖后同一组量重测（实测 `logs/percentile_drift_20260930.log:23-26`、`logs/daily_score_variance_20261003.log:4-6`）：900 个信号日，清仓线 0.00875 中位排 P88.82（最松 P28.56 = 2024-02-05、最紧 P97.65 = 2024-01-05，极差 69.1pp），建仓线 0.01354 中位 P95.94（最低 P41.28 = 2024-01-19、最高 P99.47 = 2024-01-05，极差 58.2pp），过建仓线只数日均 53.7 / 中位 38 / 最少 5（2024-01-05）/ 最多 552（2024-01-19），相邻两日只数变化的标准差 40.4 |
| **当天分数分散度（截面标准差）** | 同一天全部股票的分数减均值除标准差得到的那个标准差，它决定一条写死的线当天能圈到几只。实测 900 个信号日：中位 0.00772，最小 0.00468，最大 0.01609（3.4 倍），与过建仓线只数的等级相关 +0.4326（`python research/daily_score_variance.py` → `logs/daily_score_variance_20261003.log` §1）。配置里没有任何项能固定它：输入端每个特征每天在当天全池里被重新标准化成 σ≈1（`factors/processor.py:257-261`），输出端（分数）没有任何一步再标准化 |
| **过线名单日间重合度（Jaccard）** | 相邻两天"过建仓线名单"的交集只数 ÷ 并集只数，1 = 完全相同。实测 899 个相邻日对中位 0.32、平均 0.32（`logs/daily_score_variance_20261003.log:15`）；同一只股票相邻两天的分数差中位 0.00210 = 当天截面标准差的 27%（`:13-14`）；面板端 momentum_5d / rsi_14 相邻两日绝对差中位 0.308 / 0.294（当天截面 σ ≈ 1.0，`:18-19`） |
| **分数带位** | 仓位跟着分数走，不是等权平摊。分数越高买越厚，加仓要"涨够一个台阶（Δ）"**或**"够到绝对补仓线"（现取 P97 = 0.01807，2026-09-27 起开着，见下面两行） |
| **建仓 / 补仓 / 减仓 / 清仓** | 四种动作，只在每月最后一个交易日（次一个交易日开盘成交）决定 |
| **新仓上限 vs 在市只数上限** | 前者限制一轮能新开几只，后者是组合里总共允许几只。**回测看的是后者**：平均持仓 4.0 只，上限 12 只是天花板，不是常态 |
| **单票上限 / 持仓上限** | 一只股票最多加到多少（16%），再涨也只到这儿。**现行参数下这个上限偶尔才够得到**：建仓最高 8%，往上只能靠补仓，45 轮里补仓成交 **12 次**（要开下面那条"补仓绝对线"才到这个数，只按台阶 Δ 时是 1 次），其中只有一笔一路顶到 16% |
| **台阶 Δ** | 分数要比上次动作点再涨多少才算"又强了一档"，没到就不动。Δ = max(0.005, 建仓分数 − 建仓线)，建仓时冻结 |
| **补仓绝对线（`add_score_line`）** | 2026-09-27 新加的旋钮，是补仓的**第二条标准**：分数现在够不够强，够到这条线就补一档。与"涨够一个台阶 Δ"是**或**的关系（任一成立即补，不是两个条件都要满足）。代码里的默认值是 0 = 关闭，**`config.yaml` 现取 0.01807 = P97（已采纳为默认）**。实测：45 轮补仓 **1 → 12 笔**（其中 10 笔只由这条线促成）、累计 162.09% → **200.92%**（+38.83pp）、Sharpe 1.663 → 1.873、回撤 19.04% → 19.95%；但同一改动换到"静态上限 30% / 4 只"那档是 **−65.97pp**（塌陷在 2024：分年 +42.3%→+1.3%），五种暴露层里两档为负、且**五档回撤全部变差**（+0.91~+6.72pp），所以它是**带条件的采纳**：名额一收到 4~7 只、或总仓位一压到 30%~45%，就要把这行改回 `0.0`。⚠ 线一开，**净值自己的路径噪声带就变宽**（期末净值跨度 6.7pp → 27.4pp、回撤带 0.81pp → 8.80pp，`logs/cost_audit.log` §0），所以 +38.83pp 只是全带的 1.4 倍，不能单独当"确定更赚钱"。那 12 笔补仓在日志里逐笔带分数与金额，当日 12/12 全额成交、其中 1 笔顶到 16% 单票上限。最差那档为什么崩也逐笔查过（`python research/add_line_2024.py`）：不是补的票亏钱（13 笔增量钱自身 +118,270 元；**留一法**〔一次只取消一笔补仓、其余照旧，再整段重跑，看总收益变好还是变差〕最伤的一笔也只值 +5.46pp），而是补仓把建仓的坑占了 —— 2024-04-01 那笔 50,468 元补仓让**可用额度**〔引擎当轮留给"新花钱"的上限：拿"总仓位上限 − 补仓预留"和"总仓位上限 − 已有持仓"里更小的那个，见 `utils/position_policy.py::_apply_budget`〕从 25.1% 掉到 15.6%，当场挡掉后来赚了 +459,906 元的 300641。它只触发、不消耗台阶：由它促成的补仓不推进参考分数，减仓条件一字未动（实测 trim 13 / exit_by_trim 6 与关线时完全相同）。`docs/entry-位置管理.md` §8-E、`python research/add_line.py` |
| **参考分数（ref_score）** | 台阶 Δ 的起算点 = 上一次**成交**动作后的分数基准。补一档就把它抬高一格、减一档就压低一格；单子没成交则不推进，下月同一档条件还成立会自动重试 |
| **减一档即清仓** | 建仓 5% − 减一档 5% = 0，低于最低持仓 2.5%，所以分数不够高的持仓一减就整个卖掉（`exit_by_trim`）。实测 45 轮：真减仓 13 次 vs 一档即清仓 6 次（清仓线还在 0 时是 30 / 46）——**现在的清仓绝大多数是分数直接掉破线**，125 次 |
| **减仓价锁** | 减仓成交时记下成交价，此后 60 自然日内"现价高于它就不许补仓/重建"（价格天花板，不是地板）。只有 `trim` 成交才记账，所以它跟着减仓一起变少：实测到期自动解除 **8** 次、真正拦住重建 **0** 次（`research/action_notes.py` → `logs/action_notes.log`；旧档 55 / 1 是清仓线为 0 时） |
| **等比降杠杆（de_gross）** | 暴露层把本轮总仓位上限压到低于当前仓位时，按现有权重等比卖出到上限。属于风险动作，不推进分数状态、不设减仓价。实测 10 次 |
| **总仓位上限** | 一轮最多允许动用多少比例的钱。不是一次定死，是每月重算 |
| **目标波动** | 把总仓位上限锚在"全池等权最近 20 天真实波动 = 年化 10%"上。波动大就自动减仓 |
| **RankIC 门控** | 模型近期没效（IC 为负）时，总仓位上限直接减半、并且禁止开新仓 |
| **纯带位 vs 带暴露层（复核档）** | 同一份分数、同一套费率，只差"要不要开组合级降杠杆/门控"。任何结论都要在两档上各看一遍：只在一档成立的差异，很可能是路径噪声而不是规律。例：把清仓线从 0 抬到 P84（现行默认档上量的），带暴露层多 12.68pp、纯带位多 26.17pp，看着同向 —— 但回撤那一列**一个变差 0.69pp、一个变好 4.23pp**；把补仓线关掉再测同一处改动，两档的回撤符号又各自翻了一次（`docs/entry-位置管理.md` §8-C） |
| **欠配** | 目标仓位没买到，剩了一堆现金。主因是仓位上限本来就低（暴露层给的上限平均 45%、含门控最低 14%，于是平均目标仓位只有 36.1%），不是撮合失败 |
| **费前 / 费后** | 扣没扣手续费和滑点。本项目报的**全是费后** |
| **交易成本占比** | 全部佣金/印花税/滑点之和 ÷ 初始本金（5.92%），不是占收益的比例 |
| **滞后期（lag）** | 把因子往前挪一天，确保成交那天看不到未来的数据 |
| **停牌 / 一字板** | 不成交 / 涨停买不进、跌停卖不出。回测按**成交那一刻的开盘涨跌幅**判（开盘就是一字板才算买不到），模拟盘按最新一根的涨跌幅判 |
| **三条链（回测 / `paper-trade` / `run_daily`）** | 同一份分数、同一个仓位模块的三种跑法，**差别在什么时候成交**：回测 = 月末收盘决定 → 次一个交易日开盘成交（本文所有数字的口径，+200.92%）；`main.py paper-trade` = 挂单要等下一次月度撮合，**晚约一个月**（同一份分数重放只有 +25.52%，别拿它对照回测）；`live/run_daily.py --simulate` = 当天分数按当天开盘价成交，**早一天、偏乐观**。只有 `run_daily` 写出的**指令文件**是你要照做的东西 |
| **前视（look-ahead）** | 用了"当时不可能知道"的数据。回测最大的坑，§6 专讲 |
| **逐变量对照（四档 / 2×2）** | 同时改了两处时，把"只改 A、只改 B、两处都改、两处都不改"各跑一遍，差值才能归到某一处头上（`research/fill_and_threshold.py`）。**坑**：对照臂要的"旧参数值"必须写死在脚本里，不能读 `config.yaml`——config 一旦搬到新值，"旧线"和"新线"就成了同一个数，四档塌成两档，差值算不出来 |
| **重取行情的改写范围** | 2026-10-03 实测：09-30 把行情补到 09-29 并重算面板后，旧/新面板能配上的 1,284,545 行里，25 个因子列有 **97.5%~99.9% 的格子数值不一样**（`logs/panel_diff_20261003.err`），但**同一天内谁高谁低的次序几乎没动** —— 逐日"旧值 vs 新值"的排序相关中位 **1.0000**、1388 天里最小 **0.9999994**、同一只股票新旧值的绝对差中位按列在 **0.0007~0.0017** 之间（标准化后的单位），`python research/panel_rank_shift.py` → `logs/panel_rank_shift_20261003.log` §2。同一天的股票池 2023 年日均 932.6 → 936.0 只、总名字数 1000 → 1004（同文件 §1/§3）。所以面板这一层是"小数第 3 位的抖动"，不是把历史重写了；两条净值为什么差 161.82pp 见下面"重训噪声"那一行 —— 不是面板改写本身，也不是早停切点（两行各有实验） |
| **早停迭代数（`best_iteration`）** | 每一折训练都在"训练集尾部 15% 的行"上决定何时停（`main.py:324` `mid = int(len(X_train) * 0.85)`）。这个切点按**总行数**算，所以行数一变，落进验证集的是哪些样本就跟着变，选出来的迭代数大幅移动（旧臂 → 新臂：499→219、344→400、394→213、269→500、475→499、500→500、500→499、245→369，实测 `logs/h5_train.log` 与 `logs/train_20260930.log` 各自的"训练完成"行）。**但它不是两条净值差 161.82pp 的原因**：折 6 两臂的迭代数都是 500（没变），逐日分数排序相关仍然只有 0.8642，和迭代数变了的折一个水平（实测 `logs/refit_noise_20261009.log`） |

| **调仓日名单重合度** | 两个数据版本在同一个月末决定"买进谁"之后，交集只数 ÷ 并集只数。实测 **0.28**：28 个有买入的调仓日里只有 **1 个**名单完全一样（`logs/why_162pp_20261003.log` §6，脚本 `research/why_162pp.py`）。它和"月末分数前 12 只重合 6.5~6.9 只"（`logs/pred_diff_20261003.log`）不是一回事：后者是分数排出来的，前者是过线、仓位上限、可用现金、整手取整、一字板全部走完真正下单的那份 |
| **路径噪声带** | 只改一个跟钱有关的数（费率、滑点），会把"哪天买多少股"整条路径抖一遍，净值就随机摆动。**要按列量，而且它跟着参数变**：现行默认档（补仓线开着）期末净值跨度全带 **27.4pp**、"只免掉一项费率"那四档的同族带 **9.87pp**；回撤那一列 **8.80pp / 0.43pp**（同一轮探针，`logs/cost_audit.log` §0）。补仓线关着时同一条探针只有 6.7pp / 0.81pp —— 那条线让每一轮的持仓更依赖"哪一笔先成交"，所以带自己变宽了。小于各自这条带的档位差不能说"更好" |
| **增量追加（历史一格不改）** | `data/downloader.py:304-324` 的 `_cache_slice`：请求的起点不晚于缓存已有的起点时，只向数据源补尾巴，历史那部分不重取。2026-10-09 用 `--start 20260925` 走的正是这条路：旧/新面板能配上的 1,292,178 行 × 25 列里，两边都有数的 **32,138,798 个格子 100% 完全相等**（另有 165,652 个格子两边都是空值，属因子预热期，不算差异；一边空一边有数的 **0** 个），实测 `logs/panel_rank_shift_20261009.log` §4、`logs/probe_newdays_20261009.log` §2。对照 09-30 那次是重取，历史有 97.5%~99.9% 的格子在小数第三位抖动 —— 想比较两个策略版本，用增量追加才不会把历史一起换掉。2026-10-09 补完尾巴重训后：8 折 `best_iteration` 全同、前 7 折 RMSE/RankIC 逐字相同、回测 +39.10%、282 笔与上一版相同，只有尾部三天（09-22~09-24，无持仓）与基准/超额两个尾部指标动了（实测 `logs/train_20260930.log` 对 `logs/train_20261009.log`、`logs/backtest_20261009.log:5-13`）——补未来几天不动模型，是"训练没有吃未来数据"的对照 |
| **预测末尾比行情末尾早 5 个交易日** | 一条分数要有"事后 5 个交易日的实际收益"才进得了训练和评估（`models/dataset.py:46` `close.shift(-horizon)`，`config.yaml:48` horizon=5），所以 `predictions.parquet` 的最后一天 = 行情最后一天往前数 5 个交易日。2026-10-09 实测：行情缓存里 988 只最后一根是 10-08、11 只是 10-09（09-25 中秋休市，没有 bar），预测就只到 **09-24**，而 09-24 那天**只有那 11 只有分数**（09-23 有 999 只）—— 它们的第 5 个交易日正好是 10-09。月末调仓日取"当月最后一个有分数的日子"（`backtest/engine.py:574-578`），于是这一版的 9 月调仓日落在只有 11 只候选的 09-24 上（最高分 0.01014，没过建仓线 0.01354，所以 0 笔交易） |
| **截面（cross-section）** | 同一天里，在全部候选股票之间互相比较（谁比谁强）；同一只股票在不同日期之间比较叫"时序"。RankIC、当天分数分散度都是截面上算的量 |
| **状态切换（regime switching）** | 先判断"当前处于哪一档市场状态"（如高波动 / 低波动），不同档用不同参数或不同仓位上限，隔一段时间重判一次；与"每天用同一套参数"相对 |
| **隐马尔可夫模型（HMM）** | 状态切换路线的常用工具：假定市场在少数几个不可直接观测的状态之间切换、每个状态下涨跌幅分布不同，用历史序列反推每天最可能属于哪个状态。量化行业通用方法，本项目代码里没有这一项 |
| **标签（label）** | 模型要预测的答案，与输入（因子）相对。本项目 = 未来 5 个交易日的相对涨幅：`models/dataset.py:46` 算 `close.shift(-horizon) / close - 1`，`config.yaml:48` `horizon: 5` |
| **容量（capacity）** | 一个策略能容纳的资金规模上限：资金越大，每次买卖占当日成交量的比例越大，对价格的额外推动损失（冲击成本）也越大；这部分损失大到超过策略赚的部分时，就是容量上限 |
| **两臂交集档（只买两边都过线的股）** | 组合分 = 两臂分数逐日取较小值：`min(a,b) ≥ 建仓线` 严格等价于两边都过线，所以买入候选 = 两臂过线名单的交集；卖出是"任一边想卖就卖"（组合分跌破清仓线 0.00875）。它不是把某一臂的成交取子集——组合分重新决定了买卖排序，笔数也会变。2026-10-09 测 6 对（脚本 `research/seed_intersect.py`；支架与单臂逐行一致，单臂数字与档案逐字对上：旧 42 +200.92%、旧 7 +35.70%）：**6 对里 5 对同时低于两个单臂、只有旧 0∩5 略高于双方**——旧 42∩7 **+18.42%**（对照 +200.92 / +35.70）、旧 42∩3 **+93.55%**（+200.92 / +96.39）、旧 0∩5 **+17.41%**（+12.64 / +15.42）、新 42∩7 **+14.99%**（+39.10 / +21.14）、新 1∩0 **+36.63%**（+50.41 / +44.62）、新 42∩13 **+17.43%**（+39.10 / +32.33）；交集值落在 +14.99%~+93.55%（中位约 +17.9），**右尾被切掉**——+200.92% 靠的是单臂独有的名字（300641 2024-04-01 只有放行的种子买得进），且"任一边想卖就卖"让换手更高（交集 310/296/318/308/285/299 笔 vs 单臂 264~298 笔）。候选诊断：每个调仓日过线平均 48~55 只、交集 33~36 只，45 个调仓日里交集为空 0~1 个（实测 `logs/seed_intersect_20261009.log:1005`、`:3692`、`:6191`、`:8014`、`:16018`、`:22602`、`:30122`、`:36931`、`:41429`、`:23612`） |
| **相对名次 / 排名法（rank）** | 不看分数绝对值够不够高，只把当天全池按分数排序、取最前一批（如前 6% 或固定只数）。行业量化选股的标准做法（推断，本机没有实验）；本项目现行用的是另一条路：比较三条固定的绝对分数线。已知差别：绝对线的当日有效分位会漂（极差 58.2~69.1pp，见上面"有效百分位"行），排名法每天取的都是"当期分数最高的一批" |
| **组合优化（portfolio optimization）** | 把预测分数、风险估计、约束（单票上限、行业/市值偏离上限、与上期权重的偏离上限 = 换手控制）放进同一个最优化问题，一次解出全部持仓权重。行业机构标准做法（推断，本机没有实验）；本项目用逐股状态机（分数带位）替代，本机代码里没有这一项 |
| **广度（breadth）** | 同一期独立下注的只数（乘以每年调仓次数 = 年下注数）。行业做法是同时持有几百只，让单只的运气对组合的影响变小。本项目平均持仓 4.0 只（`docs/入门.md:138`），与 IC 的换算见下一行 |
| **主动管理基本定律（fundamental law of active management）** | 行业经验公式 IR ≈ IC × √广度（Grinold 1989；推断，本机未验证）：IR = 信息比 = 超额收益 ÷ 跟踪误差。按本项目数推：IC 日均 0.0162（`logs/train_20261009.log:7-22`）、4 只×12 个月 → 年化 IR ≈ 0.11；100 只 → ≈ 0.56。公式假设下注互相独立、实际做不到，所以算出来是上界 |

## 5. 十个已知的坑（别踩）

**坑 1：它经常欠配，别以为满仓在跑。**
回测里平均目标仓位只有 36.1%，欠配 41 次、那些次平均滞留 130 万现金——比仓位本身还值得警惕。
根因不是撮合失败（买入只挡了 1 笔、卖出被挡 0 次），是暴露层给的仓位上限平均只有 44.8%、
最低 14.2%（含 IC 门控；只算目标波动那一步缩放是中位 47.4%、区间 28.5%~90.3%），
12 个名额根本用不满。**这是规则的固有特征不是 bug**：它宁可拿着
现金也不放宽仓位。后果是涨得猛的年份白放着一大块钱——**2025 年就是这么一次**：池内等权涨
+41.6%，这套规则只拿到 +32.1%（那一年中证1000 是 +27.5%，它跑赢了指数 4.6 个点，输的是
"整个池子"）。分年口径 = 年内日收益复利，出处 `research/annual_baseline.py` →
`logs/annual_baseline.log`：2023 +8.022% / 2024 +58.327% / 2025 +32.091% / 2026 +33.201%，
**四个日历年对指数全是正超额**（最薄的是 2025，+4.60pp），但**只有 2025 这一年跑输池内等权**
（−9.47pp），其余三年对两个参照都赢。

**坑 2：别拿历史最好的那组参数当真。**
项目里有过一次教训：把建仓线横着扫一遍（那是 horizon=20 那一版的扫描），不带暴露层的四档
累计收益从 +121% 一路排到 +168%
（Sharpe 0.80~0.98），"最好那一档"是 12 个组合里挑出来的冠军——换一份数据它不一定还是冠军。
现行默认档（5 日标签，建仓线 0.0135 / 强线 0.0181 / 清仓线 0.00875）不是"扫出来的最优"，
而是**按分数分位点重推**得到的（P94.00 / P97.00 / P84.01，建仓线与清仓线都是 2026-09-26
动的：前者从 P84.57 抬到"最前 6%"，后者从 0 抬到"掉出最前 16% 就撤"，见 `config.yaml` 的
`position_policy` 注释）。扫描表只留作对照（在 `Quantlab/README.md`「阈值标定与全档实测」），别再去找最大值。
**抬清仓线这一次尤其别当成"找到了更好的参数"**：在现行默认档上它买到的是累计（+12.68pp，勉强出
9.87pp 的同族噪声带），回撤那一列**反而变差 0.69pp**（19.26% → 19.95%），换手结构还变了
（减仓 29 → 13 次、"减一档即清仓"43 → 6 次）；而且同一处改动换一层暴露层，边际从 −8.45pp 摆到
+24.58pp（`logs/sell_line.log` §4，机制见 `docs/entry-位置管理.md` §8-C）。⚠ 补仓线关着时同一处
改动读出来的是反的（累计 +2.87pp 在噪声里、回撤 22.67% → 19.04% 变好），两版只能有一版和现行
参数搭得上。

**坑 3：涨跌停是"当天不成交"，不是"永远不成交"。**
回测里涨停挡掉的买入直接作废（不追单），跌停卖不掉则**一直挂在持仓里**，下次评估再试。所以
连续跌停时你会看到仓位卡着不动。**判定看的是开盘价 vs 前收盘**（2026-09-26 改）：撮合价就是
次日开盘价，早先用当日 `涨跌幅`（收盘 vs 前收）判，会出现"开盘一字跌停、收盘拉回 −3%"那天
回测按开盘价把卖单成交掉的事——实盘那张单子排在跌停板上出不去。板块幅度 10%/20% 由代码前缀
决定（`utils/market_rules.py` 的 `at_limit_up/at_limit_down`，两边同源，改只改一处）。
每日链 `live/run_daily.py` 只能拿到"最新一根 bar 的收盘涨跌幅"，所以它标的是**今天**的状态，
明早开盘能不能成交没人知道；被涨跌停或停牌挡掉的名单会直接写在指令文件里，让你看得见
（它不假装成交）。

**坑 4：模拟盘不会"记住"你手动改过的仓位。**
持仓状态存在 `live/state/`（这个目录在 `.gitignore` 里，删了就等于从零开始）。你手动加仓、
部分卖出、或者换账户，都要同步到状态文件，否则下一次跑出来的指令会基于错误持仓。

**坑 5：分数低 ≠ 该做空。**
这套系统只做多。所有股票都在"买 / 不买 / 卖出手里的"三种状态里，**分数再低也只是不买**，
跌破清仓线也只卖自己持仓里的。分数全线跌破清仓线时它会清仓并留下大量现金（然后空等），
但不会变成融券或股指期货。顺带把"清仓线以下"这件事的量级摆正：现行线（P84）之下本来就是
常态——逐月有 **65%~96%** 的名字分数落在清仓线以下（`research/monthly_scores.py` →
`logs/monthly_scores.log`），所以这条线是**轮换用的门槛**，不是"极端行情才碰得到"的保险丝。

**坑 6：回测里没有滑点以外的冲击成本。**
单次换手中位 11.9 万元（298 笔的中位数 118,633 元，`logs/cost_audit.log` §1）、约占个股日成交
中位数（1.46 亿，`logs/survivorship_probe.log`）的 0.081%——这个规模上午盘挂单冲击可忽略。
**但别拿这套参数直接跑 1000 万**：仓位放大 10 倍，参与率到 0.81%，固定千一滑点就不够用了，
得改成随成交量放大的冲击成本模型。

**坑 7：股票池是"今天还活着的 1000 只"，绝对收益整体偏乐观。**
股票池取自中证指数公司的**当前**成分股接口，所以整段回测里没有任何一只股票会退市、会被
调出（实测 0/1000 只中途缺席）。真实历史里 2023~2026 有一批小票跌到退市，它们不在数据里，
策略就没在它们身上亏过钱。量级已经量过（`research/survivorship_probe.py` →
`logs/survivorship_probe.log`）：同期退市、能取到行情的 147 只，窗口内买入持有**中位
−87.7%**、只有 3% 为正；把这 147 只塞回等权池，等权均值从 +58.5% 掉到 +39.3%（折年化
+13.3% → +9.4%，**约 3.9pp/年**）。这是**下界**（只拿得到交易所终止名单，"当年在指数里、
后来被调出"那一整块免费接口取不到），也别用"反正买不到"打折——这批名字中位日成交额
0.39 亿，够本策略下单一万块的规模。读法：**这个偏差同时抬高策略和等权基准**，所以
"跑赢等权组合"那部分相对结论还能看，"+200.92%" 这个绝对数要往下减几个点。

**坑 8：`paper-trade` 那条链的成交比回测晚一整月，它的结果不能跟回测对照。**
三条链用的是同一个"该买多少"的模块，但**什么时候成交**不一样：回测是"月末收盘决定 →
次一个交易日开盘成交"（这才是本文所有数字的口径）；`python main.py paper-trade` 把订单
交给模拟券商后，要等到**下一次**撮合才成交，而它的循环是每月跑一次 —— 于是信号到成交之间
多塞了整整一个月。实测：回测第一笔在 2023-02-01，`paper-trade` 第一笔在 2023-03-01；
同一份分数、同一套费率全历史重放（2021-01-04 ~ 2026-09-22），`paper-trade` 只有 **+25.52%**（223 笔、
胜率 47.8%），回测是 **+200.92%**（298 笔）。**这 175.40 个百分点是"晚进场"造成的，不是
规则分歧，也不是"实盘会差这么多"**。反过来，`live/run_daily.py --simulate` 的纸面撮合
是**当天分数按当天开盘价**成交，比回测早一天、偏乐观（收盘后你买不到当天开盘价）；
它生成的**指令文件**没这个问题（写明次日执行）。细节与出处见
`docs/entry-位置管理.md` §7 那张三链对照表。

**坑 9：没装 `cn-stock-holidays` 就不认识节假日 —— 所有工作日都被当成交易日。**
`utils/calendar.py:11` 那个包是**可选导入**，取不到节假日表时 `is_trading_day()` 对任何
工作日一律返回 True（`utils/calendar.py:86-94`）。周末没问题：今天（2026-09-27 周日 00:25）跑
`run_daily.py` 正确跳过，并打一行 WARNING「cn-stock-holidays 未安装，交易日历仅排除周末，
不含节假日」（`logs/live_smoke.log`）。**但国庆那种工作日假期它不会跳过**：那天照样走完全程
—— 下载拿不到新 K 线 → 用**上一个交易日**的收盘算分数 → 写出一份文件名带假期日期的
`live/output/orders_YYYYMMDD.csv` → 加 `--simulate` 还会按那根旧 K 线的开盘价"成交"。
**自查**：看指令文件名里的日期在行情软件里是不是交易日；分数是昨天的这件事不会报错。
**修法**：`pip install cn-stock-holidays`（离线数据包），装完那行 WARNING 消失。

**坑 10：文档里"P94 / P97 / P84"是死的标签，线的实际松紧每天在漂。**
三条阈值写在 `config.yaml` 里是**绝对分数**，运行时只做大小比较；那三个分位标签来自
**整份** `predictions.parquet`（854,322 个配对观测）的一次性标定。也就是说**没有任何东西
每天重算百分位**（扫五个运行目录：分位数调用 1 处、**对分数的 0 处**，那处算的是持仓天数；
另有 5 处 `.rank()` 服务 RankIC 与旧 Top-K 的 rank/weight 列，都不产出阈值），但市场水位一动、
每 6 个月换一次模型，同一条线在当天截面里排第几就跟着动：
清仓线 0.00875 的日度有效分位中位 **P87.80**、区间 **P28.97~P97.50**（极差 68.5pp），
建仓线 0.01354 中位 **P95.72**、最低 **P41.73**。最直观的后果在"过线只数"上：
2024-02 日均 **204.5** 只过建仓线（那个月建仓线只挡到 P78），2026-09 日均只剩 **23.8** 只
（P97.61）—— 同一句"只买最前 6%"，一个月给出 200 只候选，另一个月给 24 只。
**自查**：`python research/percentile_drift.py`（实测 3.5~4.1 秒，不跑回测）出逐日/逐月/逐折三张表，
§5 还会告诉你"改用最近 6 个月重标，三条数要改成 0.00961 / 0.01369 / 0.01760"。
**要不要重标**：现行三条是 2026-09-26 在全样本上标的，§5 里换窗口的偏移最大
**0.00187**（最近 12 个月的强线），相当于 0.37 个 Δ 档（`step_score_floor` = 0.005）——
没到需要频繁搬动的量级；真正必须重标的只有"换了 `model.horizon` 或因子集"那一次（见 §7）。

## 6. 为什么回测结果能（稍微）信：防前视

**前视（look-ahead）= 用"当时不可能知道"的数据做决定**。这是量化回测最常见的自欺，也是这套
系统上唯一一次"整个回测作废级别"的 bug。

### 出过一次真事故

2026 年那次改造（把股票池从沪深300 换成中证1000）之后，回测算出的净值曲线在**起点附近
剧烈跳动**——那不是策略好，是引擎在第一天用了后面才知道的价格。修复之后才有现在这些数字。
这条修复比后面任何参数调整都值钱，所以写在最前面。

### 判据只有一条

**把某个切点（2025-06-30）之后的数据毁掉，切点之前的一切必须一模一样。**

可复现脚本：`python research/no_lookahead.py`（实测 23 秒，跑 3 个全量回测 + 因子重算）。
它跑三件事（数字 = 现行 P94 档这一轮，`logs/no_lookahead_p94.log`）：

| 探针 | 怎么做 | 实测 |
|---|---|---|
| 价格扰动 | 切点之后所有价格 ×0.5，重跑全量回测 | 切点之前 887 天净值最大差 **0.00e+00 元**、成交流水差 **0 笔**；期末净值 3.0430×（全量档）→ 2.3665×（296 笔，证明扰动真的生效了，不是空跑） |
| 历史砍断 | 切点之后整段砍掉，再跑一遍 | 期末 1.8416×（585 天、成交 298→188 笔），切点前仍然 0 差异 |
| 因子重算 | 只用切点前的 K 线重算 60 只股票的因子，逐格比对 | 1,616,160 个单元格里不一致 **0 格** |

"期末净值掉了这么多"不是坏事，恰恰是探针该有的样子——扰动生效了而过去没变，才叫无前视。

同一条探针还顺手对了一次账（§4）：298 笔流水的 Σ已实现盈亏 +2,043,003 元 = 净值变动
+2,043,003 元，倒挤浮动盈亏 0 元（期末空仓，本来就该为 0）。**如果按笔盈亏的口径算错**
（例如"卖额 − 卖出费"、不扣买入成本），同一个策略会报出 +19,668,423 元 = 净值变动的
9.6 倍——这就是当初那个 bug 的形状。

`model.horizon: 5` 换标签之后重跑了一遍，结论不变。顺带一提：5 日标签让 walk-forward 的
训练窗口重叠从 8 个信号日降到 **0 个**（44 个信号日全部干净），上一版 20 日标签是有 8 个
落在重叠区里的。

### 结构上防前视的四处改动

读代码时按这个顺序看：

1. **因子一律 lag 1 期**（`factors/processor.py`）：所有截面处理只做 `groupby("date")`，
   不跨日期。
2. **标签绝不进特征**（`models/labels.py`）：`close.shift(-h) / close` 这个未来收益率
   **只**进训练目标。这条有测试兜底。
3. **收盘决定 → 次日开盘成交**（`backtest/engine.py`）：信号日收盘决定，次一个交易日
   撮合，涨停买不到、跌停卖不掉、停牌不成交。
4. **暴露层只看已兑现的 IC**（`utils/exposure.py`）：计算 IC 时只取"观测日 ≤ 评估日 − h"
   的样本，还没走完的标签直接排除。

还有基本面：接口只能拿当前快照摊到历史上，所以默认关闭（`use_spot_data: false`）。

### 一处不影响前视、但你要知道的粗糙

`factor_panel` 的行序不按日期单调，所以训练脚本里"取尾部 15% 做早停验证"切到的不是
时间上最后的 15%。未来数据仍然进不去（日期过滤在切片之前），但早停用的验证片段是散布在各期的。
这条记在 `Quantlab/README.md` 末尾，改它需要重排面板再重训，目前没排上。

## 7. 想改点什么，先搞清这些

`Quantlab/config.yaml` 是唯一入口，改之前先看清改哪一段要重跑到哪一步：

- 改**数据源/股票池/日期范围**：重跑 `download` → `factors` → `train`。
- 改**因子/模型标签周期**（`model.horizon`）：重跑 `train`（8 折全量 Walk-Forward 训练，
  现行 h5 实测 57 秒；h20 那一版是 28 秒。面板重建在 `factors` 那一步）→ 之后**阈值必须重推**（见坑 2），
  跑 `python research/calib_stats.py`（分位点、每日过线只数、顶端集中度、暴露层输入分布，
  实测 6 秒）或
  `research/policy_grid.py`（还要横着扫一遍档位）。
- 改**仓位规则**（`position_policy` / `exposure_overlay` / `backtest`）：只需要重跑 `backtest`。
- 改**成交判定/撮合**（`utils/market_rules.py` 的 `can_fill`、`backtest/engine.py`）：重跑
  `backtest` **并且**重跑 `python research/no_lookahead.py`（引擎改动必须重新证明没前视）。
- 改**交易成本**：`market` 那一段。**回测和模拟盘读的是同一份费率实现**——模拟盘券商直接调用
  `backtest/cost.py` 的模型，下单前留钱按逐笔费用算（佣金有 5 元下限）。改了这里两边同时生效。

改完至少跑这两样确认没跑坏：

```bash
python -m pytest -q              # 118 项，不依赖网络也不依赖真实缓存
python research/no_lookahead.py  # 前视探针 + 已实现盈亏对账（实测 23 秒）
```

**阈值不能直接搬上一版的数字。** 分数分布随模型标签周期变，5 日标签下的 P94 和 20 日
标签下的 P94 不是同一个值（同一个 P84 分位点：h5 实测 +0.00875，`logs/calib_stats.log` §1）。现行那三条线
（0.01354 / 0.01807 / 0.00875）是在当前这份 `predictions.parquet` 上重推的（复核正好落在
P94.00 / P97.00 / P84.01）；换缓存要重新推，`config.yaml` 的 `position_policy` 注释里记着这件事。
**别把新清仓线 0.00875 和"上一版建仓线 0.00892"当成同一个门槛**：两个数只差 0.00017 是巧合
（前者 = P84.01，后者 = P84.57，由 `logs/calib_stats.log` §3 的 n=131,869 ÷ 854,763 反推），
语义一个管"掉出最前 16% 就卖"、一个管"排进最前 15.4% 才买"。
改分数线之后要多跑的那两条复核，除了 `calib_stats.py` 还有 `research/sell_line.py`
（清仓线四档 + 五种暴露层上的边际，实测 50 秒）和 `research/monthly_scores.py`（实测 1 秒）。
