# 仓位规则入门：模型给出分数之后，钱是怎么分的

读完这篇你就能看懂回测和每日指令里的每一个仓位数字。所有规则都写在
`Quantlab/utils/position_policy.py`（个股层）和 `Quantlab/utils/exposure.py`
（组合层）里，参数在 `Quantlab/config.yaml`，本文数字与这两个文件逐条对齐。

读这篇之前不需要任何准备。只需要一个前提：这台机器上有一个模型，它每个交易日收盘后
会给全市场 1000 只中小盘股票各打一个分，**分数 = 模型预测这只股票未来 5 个交易日能涨多少**。
+0.0158 就是预测 5 天涨 1.58%。模型只回答"下一段五天谁更强"，不回答"该买多少、什么时候卖"。

**后半段那些仓位数字不是拍脑袋定的**，而是拿模型分数在历史上排序的位置（分位数）反推出
来的——"建仓线定在 P94、强线定在 P97、清仓线定在 P84"，意思是"只买模型排在最前 6.0% /
3.0% 的那批，手里的票掉出最前 16% 就整只清掉"。怎么从分布里挑出这三个点、以及为什么挑在
这儿而不是别处，见 `Quantlab/README.md`「阈值标定与全档实测」一节，本文只给结论。

---

## 1. 一句话规则

> **分数决定买不买、买多厚；涨得更多才加仓，涨得不够就不动。**
> 在这之上再压一层：**整个组合允许押多重，由市场状态逐月决定**。

第一层管每一只股票，第二层管总仓位。两层都用同一份信息、都只参考过去，所以回测和实盘
跑出来是同一套动作。第二层是 2026-09-22 之后加上的，没有它，全部风险预算会压在
"模型说这些股票会涨"这一句话上；有它之后，模型失效时仓位上限自动减半
（现行默认档 45 次评估的仓位上限平均 45%、中位 47.4%，`logs/main_backtest.log`），
模型顺风时仍然满额下注。

## 2. 八个参数

| 参数 | 现在的值 | 一句话作用 | 来历 |
|---|---|---|---|
| `buy_score` 建仓线 | **0.01354** | 分数低于它，根本不买 | 分数分布的 **P94.00**（2026-09-26 从 P84.57 抬到"最前 6%"） |
| `strong_score` 强线 | **0.01807** | 分数高到这儿，建仓就给满仓 | **P97.00**（沿用上一版"最前 3% 给满仓"的语义，与旧线 0.01794 只差 0.0001） |
| `base_weight` 基准仓 | **5%** | 每笔建仓的默认厚度，也就是加仓的台阶 | 主观设定，100万本金时 = 5 万元 |
| `max_entry_weight` 建仓上限 | **8%** | 建仓那一笔再高也就 8% | 主观设定 |
| `max_names` 只数上限 | **12** | 同时在市 12 只 | 1 ÷ 基准仓 8% ≈ 12 只 |
| `sell_score` 清仓线 | **0.00875** | 分数掉到它以下就整只清仓（不补、不锁价格） | 分数分布的 **P84.01**。2026-09-26 从 0 抬上来，语义跟着变了：旧线 0 落在这套分数的 **P32.92**（854,763 条预测里 32.92% 是负分，`logs/calib_stats.log` §1），等于"要等模型预测转负、掉进最差那三分之一才撤"；新线是"跌出最前 16% 就撤"。取舍与拐点见 §8-C |
| `min_trade_value` 最小笔额 | **10000 元** | 补仓/减仓动作小于一万就不做 | 万三佣金下单笔最低 5 元，一万以下的单子费率明显变贵 |
| `add_score_line` 补仓绝对线 | **0.01807 = P97（2026-09-27 采纳为默认）** | 补仓的第二条**独立**标准：分数够到它就补一档，不必等涨够 Δ。与 Δ 是"**或**"（任一满足即补），只负责触发、**不推进**减仓的参考分数 | 2026-09-27 实测（关 → 开）：现行档累计 162.09% → **200.92%（+38.83pp，是"只免一项费率"那条 9.9pp 同族带的 4 倍、在 27.4pp 全带之内）**、补仓 1 → **12** 笔（其中 10 笔只靠这条线促成），回撤 19.04% → 19.95%（+0.91pp，出 0.43pp 同族带、在 8.80pp 全带内）。但同一改动在"静态上限 30% / 名额 4"那档是 **−65.97pp**，且五层回撤**一致恶化**（+0.91 ~ +6.72pp），方向不稳健（§8-E 有每层前后完整对照、逐笔分数，以及最差那档 2024 年"补仓抢走建仓名额"的逐笔归因）。**采纳条件：只在现行暴露层（名额 12 只 + 总仓位基线 95%）下开着；名额一收到 4~7 或总仓位一压到 30%~45%，必须把这行改回 0.0** |

"来历"那一列写"P94 / P97 / P84"，意思是这三个阈值不是拍出来的数，而是**按分数分位数反推**
出来的：只买模型排最前 6.0% 的那批（P94 = 94% 的股票比它低），最高兴的给满仓就是前
3.0%（P97），持仓掉到最前 16% 以外就清仓（P84）。

⚠ **这三个 P 是一次性标定的标签，不是系统每天重算的东西。** 线上跑的时候只做
`score >= 阈值` 的大小比较，比的是三个写死在 `config.yaml` 里的绝对数；全仓 `live/`
`paper_trade/` `utils/` `backtest/` `models/` 里**没有一处**对分数取过分位数（唯一一处
`np.percentile` 算的是持仓天数，`backtest/engine.py:439`）。所以"这条线是 P84"描述的是
**整份缓存合起来**的分布，不是任何一天的截面 —— 而它在当天截面里的排位是会漂的：同一条清仓线
0.00875，896 个信号日里排得最松的那天在 **P28.97**（2024-02-05），排得最紧的那天在
**P97.50**（2024-12-20），中位 **P87.80**，极差 **68.5pp**；建仓线 0.01354 的中位有效
分位 **P95.72**、最低 **P41.73**（2024-01-19，那天 **546** 只过建仓线，而设计意图是"最前 6%"
≈ 日均 57 只；最紧的一天只有 6 只，2024-12-20）。
逐日 / 逐月 / 逐折的漂移表和"按最近窗口重标要把三条数改成多少"出自
`python research/percentile_drift.py`（→ `logs/percentile_drift.log`，实测 3.5~4.1 秒）。

复核用的分位点则一直是**现算**的：建仓线/强线见 `python research/calib_stats.py`
（→ `logs/calib_stats.log` §1，样本 85.5 万行），清仓线复核 P84.01 见
`python research/sell_line.py`（→ `logs/sell_line.log` §1，配对口径样本 854,322），
**换缓存或换 `model.horizon` 都要重推**——分数分布整体随标签周期缩放（同一个 P84 分位点：
5 日标签实测 0.00875，20 日那一版当年落在 0.030 附近；那轮的缓存已不在，0.030 取不到复核值）。
分位点为什么挑在 94/97/84 而不是别处、以及
抬线之后"12 个名额招不满"的频率（896 个交易日里 1.6% 的日子候选不足 12 只），见
`Quantlab/README.md`「阈值标定与全档实测」。**分数分布全表见 `docs/model-LightGBM.md` §5**。
**分数线是换手/暴露旋钮，不完全是 alpha 旋钮**：拿 20 日那一版横穿
0.01~0.05 扫一遍，不带暴露层的四档 Sharpe 全程平在 0.80~0.98（累计收益 +121%~+168%），
改它主要改的是笔数和仓位水位。真正在起作用的是总仓位上限（见 §8-B）。
不过"抬线"确实也换到了一点成色：现行买线以上那 5.1 万个观测，实际 5 日均益 +1.17%，
全体只有 +0.37%（旧线 P84 以上 +0.82%）。
**清仓线改的是"动作长什么样"，比改建仓线更猛**：把 0 抬到 P84，45 轮里的动作构成从
减仓 30 / 减一档即清仓 46 / 直接清仓 82 翻成 13 / 6 / 134（`logs/sell_line.log` §2），
笔数却只多 4 笔——因为建仓线和清仓线只差 0.00479，一轮分数的中位回落就够跨过它，
"减仓带"几乎不存在了（机制见 §8-C）。
所以调它之前要先想清楚：你想要的是"少换手"还是"少风险"，这两个不是一回事。

## 3. 一只股票会经历的四件事

```
空仓 ──分数≥建仓线──→ 建仓(5%~8%，按分数线性插值)
                        │
                        ├──分数比上次动作点再涨够一个台阶 Δ──→ 补仓 +5%，封顶 16%
                        │   （或：分数直接够到绝对补仓线 add_score_line = P97，
                        │     两条是"或"；这条线 2026-09-27 起默认开着，见 §8-E）
                        ├──分数下降但仍在清仓线上方────────→ 减仓 −5%
                        └──分数跌破清仓线───────────────────→ 整只清仓
```

四个动作都在**月度评估日**决定（每月最后一个交易日看分数，次一个交易日开盘成交）。
中间那条"减仓带"在现行参数下很窄：清仓线 0.00875 到建仓线 0.01354 只有 0.00479 宽，而台阶
Δ 的下限就是 0.005，所以分数一回撤，多数名字直接掉到清仓线以下走右边那条边——45 轮实测
134 次"整只清仓"对 13 次"减仓"（`logs/main_backtest.log`）。
下面跟着两只股票走一遍，数字全部按现行参数手工算。

## 4. 例子 A：一路涨的 600001

模型给了 **0.0158** 的分数，你持有 100 万现金。建仓仓位在 5% 和 8% 之间按分数线性插值，
分数越高给得越满。

**第一步：建仓多少？**

```
0.0158 ≥ 0.01354 建仓线 → 可以建仓。
仓位 = 5% + (0.0158 − 0.01354) ÷ (0.01807 − 0.01354) × (8% − 5%)
     = 5% + 0.50 × 3% = 6.5%          介于 5%~8%，分数越高给得越满
```

当前价 10 元，一手 100 股：

```
目标市值 = 100万 × 6.5% = 65,000 元 → 6,500 股（整手取整正好 65 手）→ 实际投入 65,000 元
```

同时记住两个数：**参考分数 = 0.0158**（动作过的最高分数，后面拿它比），
**台阶 Δ = max(0.005, 1.0 × (0.0158 − 0.01354)) = 0.0050**（要涨多少才算"又强了一档"；
括号里那项只有 0.0023，所以这里**是 0.005 的下限在生效**，不是公式本身）。
台阶设下限的原因：如果某人刚过建仓线就建仓，Δ 会小到 0.0002，下一轮评估几乎必然触发补仓，
变成"每天涨一点点就天天加"。

**第二步：下个月涨到了 0.0210**

```
0.0210 ≥ 0.0158 + 0.0050 = 0.0208 → 涨够一个台阶，补一档
补仓目标 = min(单票上限 16%, 当前 6.5% + 一档 5%) = 11.5%
```

股价同期从 10 元涨到 12 元，总资产 103 万。手上 6,500 股现在值 78,000 元（占 7.6%），
目标 11.5% × 103万 = 118,450 元，差额 40,450 元 → 补 **3,300 股**（33 手，39,600 元），
补完 9,800 股 ≈ 11.4%。参考分数推进到 0.0210，下一档门槛 0.0260。

**第三步：再下个月 0.0280**

```
0.0280 ≥ 0.0260 → 又够一档 → 目标 min(16%, 11.5% + 5%) = 16%（顶到单票上限）
0.0280 ≥ 0.01807 强线 → 意味着当初若直接给它建仓，就会一次给到 8%（建仓上限）
```

到 16% 之后**只可能减少，不可能再增加**。这就是"建仓 8%、持仓 16%"的含义：
第一笔永远不超过 8%，一路涨上去最厚也就 16%。

**这个例子真正的重点在最后一步：如果第三个月只涨到 0.0240，那就一股都不加。**
0.0240 比 0.0210 高了 30 个基点，但没够到下一档门槛 0.0260，规则是**原地不动**。

这就是这套规则和 Top-K 等权最根本的分歧。等权组合的做法是"到了调仓日，把 50 只股票
各卖到 1/50、再各买回 1/50"——它假设**你对排名的信心是恒定的**，而且**必须一直满仓**。
分数带位的做法是"分数没有再强一档，我就不动手"。后者带来的后果要记住：
**账户可能长期欠配**。回测里确实如此——平均目标仓位只有 36.1%、平均手里 4.0 只（上限 12 只），
六成以上资金常年在现金里。
这不是 bug，是这套规则的定价方式：它把"没把握"直接翻译成"不押注"，而不是"按 1/N 摊满"。

还有一层保护：一次评估最多补/减 **2 档**（`max_steps_per_eval`）。分数一夜之间从 0.0135
跳到 0.0400，也只会补到 6.5%+5%+5% = 16.5% → 封顶 16%，而不是从 0 直接顶满。
这是防"单一天的模型误差决定全部仓位"。

## 5. 例子 B：涨上去又掉下来的 600002

| 时点 | 分数 | 规则判定 | 动作 |
|---|---|---|---|
| 1月末 | 0.0158 | ≥ 建仓线 0.01354 | 建仓 6.5%（65,000 元，10 元） |
| 2月末 | 0.0210 | ≥ 0.0208，够一档 | 补到 11.5% |
| 3月末 | 0.0170 | 比参考分数 0.0210 低，但 Δ=0.0050 只跌了 0.0040 | **不动**（跌幅不够一档） |
| 4月末 | 0.0120 | 比参考分数 0.0210 低够一档（差 0.0090，但 0.0090 < 2Δ） | 减仓 −5% → 6.5%，参考分数退回 0.0160 |
| 5月末 | 0.0110 | 低于建仓线 0.01354、但仍在清仓线 0.00875 上方，比参考分数又跌够一档 | 减仓后只剩 1.5% < 最低持仓 2.5% → **整只清仓** |

四点值得注意：

- **3月末"不动"是特性**。涨了又跌回去一点点不该立刻砍仓，否则模型噪声就被放大成手续费。
  规则要求跌够一整个 Δ 才动。
- **5月末是"减到碎仓不如清仓"**。减仓规则本身想把仓位降到 1.5%，但留 1.5% 的仓位意味着
  以后每次评估都要为它付一次手续费、占一个只数名额，收益却可忽略。所以规则改成整只清掉。
- **但 5月末这一幕现在是少数**。清仓线抬到 P84 之后，分数回撤通常一步就掉破 0.00875，
  轮不到"减仓减到碎仓"这一步：45 轮实测走这条边的是 6 次（`exit_by_trim`），
  而分数直接跌破清仓线被清掉的是 134 次（`logs/main_backtest.log` 的策略动作行）。
  上面那张表仍然按老路径演，是为了把两条边都走一遍。
- **清仓不受 1 万元限制**，补仓/减仓受。因为清仓是"逃生"，多小的仓位都得能关掉；
  加减仓是"进攻"，太薄的单子不该做。

## 6. 还有一层：跌价不算"涨够一档"

这条最容易看漏。规则里有两个互不相干的量：

- **分数**决定要不要动手（§3、§4 全部判据只看分数）。
- **现价 × 股数 = 实际市值**，决定你的仓位比重有没有漂。

于是会出现这种情况：600001 建仓 6.5% 之后，股价从 10 元跌到 8.8 元，分数还停在 0.0140。
**市值已经缩了 12%，仓位从 6.5% 掉到 5.8%**，但分数没跌够一档 → 规则判定"不动"。
你既没有止损，也没有补仓，就这么拿着。**这是有意的**：这套规则的止损信号只有分数，
"股票本身在跌"只能作为信息通过分数间接表达（模型看到的输入变了，分数会跟着变）。

后果也要说清楚：**同一时间所有持仓都靠一个模型判断生死**。如果市场整体砸下来，模型分数
在月度评估里还没来得及变，全组合同步回撤。这就是 §8 那层总仓位约束存在的理由。

## 7. 每日模拟盘走的是同一套规则（但**成交时点**三条链各不相同）

`python main.py paper-trade`（全历史重放）和 `python live/run_daily.py`（每日链）算仓位的
地方就是 §2~§6 那几条——同一个 `utils/position_policy.py`、同一份 `utils/sizing.py` 的股数
算式（目标股数 − 当前股数，向下取整到整手）。**不存在"回测按目标建仓、下单按现金摊派"
这种两端口径分叉** —— 钉住这条的是 `tests/test_execution.py` 里的
`test_backtest_and_live_size_the_same_plan`、`test_live_and_backtest_issue_the_same_policy_orders`、
`test_paper_orders_reserve_the_same_fee_as_the_backtest`、
`test_the_level_add_line_reaches_the_live_order_sheet`（用出厂 config 的那条绝对线造一票
"台阶差一口气、绝对线够得到"的补仓，断言指令单上真出现这一行，且把线关掉后一行都不出）
四条（该文件 33 项；带位状态机自己
另有 45 项，`tests/test_position_policy.py`；全仓 118 项，`python -m pytest -q` 实测 3.8~4.2 秒跑完（6 次））。
**但"同一套规则"只到"该买多少"为止，成交时点三条链
不一样**：

| 链路 | 信号 → 成交 | 实测（同一份分数 / 同一套费率） |
| --- | --- | --- |
| `main.py backtest`（本文所有结论的口径） | 信号日收盘决定 → **次日开盘**成交 | 第一笔 2023-02-01；全期 +200.92%、298 笔 |
| `main.py paper-trade`（全历史重放） | 挂单要等**下一个调仓日**才撮合 = **比回测晚约一个月** | 第一笔 2023-03-01；重放到 2026-09-01 = **+25.52%**、223 笔、成本 29,086 元、胜率 47.8%、利润因子 1.44（`logs/paper_smoke.log`，2026-09-27 在新默认下重跑） |
| `live/run_daily.py --simulate`（纸面撮合） | 同一次运行里先出单再撮合，撮合用的是**当天那根 K 线** = **比回测早一天** | 见 `live/run_daily.py:207`（`snapshot` 取 `df.iloc[-1]`）与 `:248`（`process_daily(today, …)`） |

另外两条小的不同：**评估频率**（回测与 `paper-trade` 都是月末信号日一轮；`run_daily.py`
每天跑，但一轮只推进一档、分数没变够就不产生指令，所以动作节奏和月度基本重合）；
**涨跌停判据**（回测按成交那一刻的**开盘**涨跌幅判，`run_daily.py` 按最新一根的涨跌幅判）。
T+1 锁仓和"可卖股数"三条链都算。

⚠ 于是有两句话不能再说：**(1) 不要拿 `paper-trade` 的净值跟回测对照**——差的 **175.40pp**
（+200.92% vs +25.52%）不是规则分歧，是"晚一个月进场"（同一份分数、同一个 `position_policy`、
同一套费率，只有撮合节奏不同）。**(2) `--simulate` 那条纸面净值偏乐观**，它用当天收盘算出的分数去拿
当天的开盘价，实盘拿不到；受影响的只有纸面净值，**指令文件本身是"收盘后决定、次日执行"，
没有这个问题**。顺带：清仓线那条改动在这条又晚又稀的链上同样表现为"更赚"
（把 `sell_score` 复制成一份 `0.0` 的临时 config 跑 `main.py --config <该文件> paper-trade`
= **+10.63%** / 235 笔 / 胜率 39.0% / 利润因子 1.16，出处 `logs/paper_sell0.log`，
⚠ **这组数测于补仓线还关着的时候，本轮没有重跑**），
但别拿它给 §8-C 的档位结论背书。

### A. 组合级暴露层：总仓位上限是市场状态的函数

分数带位只决定"买谁、买多厚"，总仓位上限是另一层（`utils/exposure.py`），它每月评估时
输出两个值：**这一轮允许用多少仓位**、**还让不让开新仓**。两个量都只用信号日收盘及
之前的信息，成交在次日开盘，所以无前视。

| 旋钮 | 作用 | 现行默认 | 怎么定的 |
|---|---|---|---|
| B 目标波动 | `上限 = 基线95% × clip(目标波动 ÷ 已实现波动, 地板, 1)`，只降不升 | 目标年化波动 **10%**；回看 **20** 日；地板 **0.30** | 10%：小资金要的是风险调整后的收益密度，10% 是"和沪深300风险同级但收益显著更高"那一档（水平本身没扫到底，见下面 §B 与 README 结论 4(d)）；20 日：反应快，45 个月末评估日给出的上限落在 **28.5%~90.3%、中位 47.4%**，其中 6/45 次被地板顶住（`logs/calib_stats.log` §6，波动输入：中位 20.0%、最低 10.5%、最高 70.1%）；0.30：市场剧震时最多砍到 28.5% 仓位，不允许砍成空仓 |
| A IC 门控 | 近 60 日已兑现 RankIC 均值 < 0 → **上限 ×0.50 且禁止新仓** | 窗口 **60 日**；标签 **5 日**；最少 **5** 个观测；乘数 0.5 | 5 日标签与模型标签一致（否则是拿别的周期表现判它），5 个观测防单点噪声；0.5 是主观设定，与目标波动一起把 45 次评估的仓位上限**平均**压到 44.8%（最低 14.2%）。注意：这一半单独开着是净负贡献，见 §8 第 3 条 |

两个量的设计原则相同：**都只用"钱已经赚到手"的信息**。已实现波动量的是全池**等权组合**
日收益的波动（`close.pct_change().mean(axis=1)` 的 20 日滚动标准差 × √252，不用组合自己的
历史，冷启动时那条数据是空的）；RankIC 只统计标签已经走完的日子，评估日附近正在形成的
标签根本不在窗口里。

### B. 为什么不是更保守或更激进

拿现行 10% 在附近扫一遍（**现行口径重扫**：h5 分数 + P94 建仓线 + P84 清仓线 + P97 补仓线 +
次日开盘判定，A 门控保持开启，只改 `vol_target_ann`；`research/h5_arms.py` → `logs/h5_arms.log`，
2026-09-27 整表重测）：

| 目标年化波动 | 累计 | Sharpe | 最大回撤 | 笔数 | 成本 | 平均仓位/只数 |
|---|---|---|---|---|---|---|
| **8%** | +190.94% | **2.03** | **12.93%** | 237 | 4.59% | 28.7% / 3.2 |
| **10%（现行）** | **+200.92%** | 1.87 | 19.95% | 298 | 5.92% | 36.1% / 4.0 |
| 12% | +199.38% | 1.67 | 24.17% | 344 | 6.92% | 41.5% / 4.8 |
| 15% | +116.75% | 0.96 | 37.96% | 433 | 6.83% | 50.3% / 5.9 |
| 20% | +144.30% | 0.94 | 42.40% | 578 | 9.24% | 65.2% / 7.7 |

Sharpe 随目标下调**一路升**（0.94→0.96→1.67→1.87→2.03），累计在 8%~12% 之间是平的
（+190.94%~+200.92%，彼此最大差 9.98pp，正好压在"只免一项费率"那条 9.87pp 同族带上，
读不出高低），只有回撤是实打实一路砍下来的（42.40%→12.93%，29.47pp）。所以：**现行 10%
不是风险调整最优**，它比 8% 那一档多要 **9.98pp** 累计、多付 **7.02pp** 回撤（19.95% vs
12.93%，Sharpe 少 0.155）——注意别再引用"多要 9.05pp 换 3.57pp 回撤"或"换一倍回撤"，
那两句分别测于补仓线开着/关着之前的旧表（关线且清仓线未抬时：8% 回撤 11.75%、10% 回撤 22.67%）。
没有免费午餐的地方在别处：`scale_floor=0.30` 意味着 8% 已经在 **11/45** 个评估日撞地板
（10% 是 6/45、12% 是 4/45、20% 是 1/45，判据 = 全池等权已实现年化波动 ≥ 目标 ÷ 0.30，
`research/floor_bind.py` → `logs/floor_bind.log`），再往下调到 6% 以下，缩放会长期顶在地板上、
**退化成静态低上限**，那就不是同一个旋钮了，而是另一个参数。静态对照（同一份
`logs/h5_arms.log`，README 的归因表转录了同一份）：静态 30% + 名额 4 只
= +49.18% / Sharpe 0.72 / 回撤 21.28%，比现行的 +200.92% 少 **151.74pp**，回撤还没省下来
（21.28% vs 19.95%，多 1.33pp）。⚠ 这一档在补仓线关着时是 +115.15% / 1.46 / 18.84%（当时
"回撤只差 0.20pp、在噪声里"那句就是这么来的），**同一处改动把它自己砸掉 −65.97pp**，
所以静态对照的绝对数不能跨参数版本引用，机制见下面第 9 条。
h20 那一版扫出来的旧表（8% 1.26 / 10% 1.22 / 12% 1.24）已被这张取代：方向相同
（往下更稳），但当时三档挤在 1.2 上下、看不出差别，现行口径下 8% 与 12% 差 0.36 个
Sharpe，是能排序的。

> **现行默认档的触发情况**：45 次评估里 IC 门控只触发 **8 次**（2023-05、2024-01~02、
> 2026-05~09），仓位上限平均 44.8%（含门控；只算波动缩放则是中位 47.4%、区间
> 28.5%~90.3%），含门控后最低 **14.2%**。后 5 次连在 2026 年那半年，那正是模型近期
> 失效最明显的时候。**这一半单独开着是净负贡献**：只开 A 是 +104.43% / Sharpe 0.64 /
> 回撤 44.43%，比什么都不加的纯带位（+154.65% / 0.77 / 47.16%）少 **50.22pp**，只换来回撤
> 小 2.73pp。**但它配在 B 上到底值多少，这一轮读不出来**：只开 B +200.48% 对 A+B +200.92%，
> 差 −0.44pp，远在 9.87pp 同族带里（补仓线关着时这里读成"A 拖累 −20.58pp"，那个数整个是
> 路径差，不是门控本身）。回撤上门控这次给的是 22.41%→19.95% 的 **2.46pp 改善**，出 0.43pp
> 同族带、却还在 8.80pp 全带之内，只能算半读。
> **门控不是回撤总开关**：**真正在管回撤的是缩放后的总仓位上限水位**：目标波动 20%→8%，
> 回撤 42.40%→12.93%，那 29.47pp 是同族 0.43pp 带的 68 倍。但**别想用静态上限复制它**：
> 静态 45%（正好等于 B 的平均上限）只有 +62.71% / Sharpe 0.66 / 回撤 28.91%，比现行少
> **138.21pp**、回撤还高 8.96pp。
> 结论：**想要更保守，去调暴露层的目标波动（§B），不要动分数线，也不要改成静态上限。**

### C. 清仓线抬到 P84：买的是什么、代价是什么

现行清仓线 **0.00875 = 分数分布 P84.01**（§2 交代了它怎么定的；旧值是 0，落在这套分数的

改动离开现行暴露层还成不成立。一次只改 `sell_score`，其余全部现行（h5 分数 + P94 建仓线
+ A+B + **补仓线 P97** + 同一套费率），`research/sell_line.py` → `logs/sell_line.log` §2
（2026-09-27 在补仓线已开的默认档下重跑）：

**0.69pp**"。两列的符号都不一致，所以下面三句话不能沿用旧版。

三句话读这张表：

1. **买到的是累计，不是回撤**。累计 +12.68pp（188.24%→200.92%）比"只免掉一项费率"那四档的
   噪声带宽（9.87pp，`logs/cost_audit.log` §0）大 1.3 倍，却只有全带（含费率全零那档，27.4pp）
   的一半 —— 只是"勉强出同族带"。回撤那一列是 19.26% → **19.95%，变差 0.69pp**（1.6 倍于回撤
   的同族带 0.43pp、在 8.80pp 全带之内），**什么都没买到**。别把这张表读成"清仓线抬上去更稳"。
2. **代价写在动作那几列**：建仓 126→132、直接清仓 82→**125**，而减仓从 29 次塌到 13 次、
   "减一档即清仓"从 43 次塌到 6 次 —— 带位规则里"涨上去再厚一点、跌一点先削一点"那条渐变路径，

   卖出的单笔变大了（中位 103,785 → 118,633 元，`logs/win_rate_bridge.log` §2）。
3. **P84 是拐点，再紧就是净亏**：往上抬一档到 P90 少 **28.85pp**（+200.92% → +172.07%）、
   Sharpe 1.873 → 1.614、回撤多 **7.30pp**（19.95% → 27.25%）——三列同向变差，方向明确；
   把清仓线抬到和建仓线同高（退化配置：建仓后任何回撤都立刻清仓）只剩 +172.44%、回撤 28.12%，

**为什么正好在 P84 附近拐弯**（这段机制只依赖分数分布，不依赖暴露层与补仓线，所以两版通用），
出处 `logs/sell_line.log` §1b：拿过建仓线的那批名字看它
下一个月末的分数（44 对相邻月末、2,461 个名字-轮观测）——过线分数中位 0.01868，下一轮
分数**中位回落 1.66pp**，**87.6%** 下一轮就掉破建仓线，**77.5%** 掉破 P84，线若抬到 P90 则
**83.6%** 掉破。建仓线只比清仓线高 **0.00479（0.48pp）**，比一轮分数的中位回落还窄，所以
一建仓、下一轮就贴着清仓线；而"减一档"掉的权重又正好低于 `min_hold_weight`，于是直接清仓。
线再往上抬就没意义：P90 与建仓线之间只剩 0.26pp，比月度分数的自然抖动窄得多。

**这条改动的回撤符号在两个层上都翻了，必须留在档案里**（同一处改动摘掉暴露层，
`logs/sell_line.log` §3）：现行默认档下纯带位是累计 +128.48% → +154.65%（**+26.17pp**）、
回撤 51.39% → **47.16%（变好 4.23pp）**。对照补仓线关着时测的同一格：+115.34% → +146.36%
（+31.02pp）、回撤 43.81% → 48.58%（**变差 4.77pp**）。逐条摆一遍：

1. 纯带位那档：回撤从"变差 4.77pp"翻成"变好 4.23pp"。
2. 带暴露层那档：回撤从"变好 3.63pp"翻成"变差 0.69pp"。
3. 连"两档唯一一致的那件事"也没了：关线时两档都换手变多（651→808 笔），开线后带暴露层是
   305→298 笔（变少），纯带位是 640→803 笔（变多）。

所以这是一道**和暴露层、和补仓线一起配套的线**，不是一句能独立成立的"抬清仓线省回撤"。
把它搬到没有目标波动的组合上，得到的是另一笔交易。

逐档边际（`research/sell_line.py` §4 → `logs/sell_line.log` §4，同一处改动、五种暴露层，

所以**没有"清仓线该抬多高"这个独立于暴露层的答案**，只有"和现行这一套（A+B + 补仓线 P97）
配套的 P84"。想复制它，得连着目标波动和补仓线一起搬。关线那一版摆幅更大（−67.07pp ~
+74.35pp），结论方向相同：这一轮五个档位互相靠拢了，但符号照样不一致。

### D. 为什么按笔胜率反而降了（53.29% → 47.74%）

出处：`python research/win_rate_bridge.py` → `logs/win_rate_bridge.log`（两档各跑一次全量
回测，同一份分数、同一套费率、补仓线都开着，**只动 `sell_score`**，实测 15 秒）。

1. 胜率是**数笔数**：现行 155 笔卖出里已实现盈亏（扣掉买入成本和双边费用之后真赚到的钱）
   为正的 74 笔 = 47.74%；旧档 167 笔里 89 笔为正 = 53.29%。差 **5.55pp**。
2. 但**总钱数没有变少**：每笔卖出的**均值**从 +11,466 元升到 **+13,181 元**（+15%），**中位**从
   +1,029 元掉到 **−859 元**（刚好穿过零线）。均值与中位符号相反 = 分布右偏（长尾在赚钱那头）加重了。
3. 赚钱那头变肥的是**尾部那一簇，不是最顶尖的一笔**：P90 从 +38,992 元升到 +46,667 元，
   但最好一笔从 +473,985 元**降到** +469,292 元；与此同时 P25 从 −7,198 元走到 −9,611 元
   （中间那批更差），P75 几乎没动（+15,352 → +15,284）。利润因子（总盈利 ÷ 总亏损）
   2.88 → 2.86，已实现盈亏合计 +2,043,003 元 = 净值变动
   （对账见 `logs/no_lookahead_p94.log` §4）。
4. 为什么会这样：清仓线抬到 P84 后，一轮月度评估里掉出最前 16% 的名字**立刻整只清掉**，
   于是"活到下一轮的"更强、"半死不活拖着"的被提前剪掉，长持仓几乎消失。
   按「完整来回」（同一只股票从建仓到清空算一段）重算：旧档 125 段、持有中位 22 个交易日、
   持有 >63 天的 11 段（那 11 段胜率 72.7%、中位 +17,567 元）；现行 131 段、中位 21 天、
   >63 天的只剩 **3 段**，而且这 3 段胜率掉到 **33.3%**、中位 **−16,315 元** ——
   长持仓那一格整列塌了。≤21 天（一轮评估内就进出完）的占比从 49.6% 升到 **56.5%**。
5. **不是成本造成的**：两档"一单要涨过多少才算赚"的**费率**几乎一模一样 —— 买入侧 13.00bp
   + 卖出侧 18.47bp vs 18.44bp = 一个来回 **0.315% vs 0.314%**。唯一动的是单笔变大：
   中位成交额 103,785 → 118,633 元 ⇒ 一单的固定成本从 327 元升到 **373 元**（+46 元）。
   这 46 元相对 P25~P75 的间距（−9,611 ~ +15,284，宽 24,895 元）是 0.2%，
   解释不了 5.55pp 的胜率位移（脚本 §2 就是专门用来排除这个解释的）。
6. **也不是"小亏变多"**：落在 −1,000~0 元之间的卖出，旧档 7 笔（占 4.2%）、现行 5 笔（3.2%），
   反而更少；0~+1,000 元的小赚也从 5 笔降到 3 笔。真正的位移发生在**几千到两万元那一档**
   （P25 从 −7,198 → −9,611 元）。
7. 读法：胜率降 = "赚钱的笔数少了、每笔赚得更多"，不等于"变差"；这一处改动买到的是
   **累计 +12.68pp**，回撤那一列反而是 **+0.69pp 变差**（§8-C —— 关着补仓线时读成"省回撤
   3.63pp"，那一版结论已经不成立）。在这种低换手、月度评估的组合里，**胜率单独看没有含义** ——
   同一段行情常被拆成好几笔卖出，所以"段口径"的胜率（45.80%）比"按笔"的（47.74%）还低。

### E. 补仓的两条标准：Δ（涨够一档）**或** 绝对线（分数够到 P97）

问的问题：补仓原来只有一个条件 —— 比上次动作的参考分数再涨够一个台阶 Δ。现在给它加
第二条**独立**条件："只要当前分数 ≥ P97 = 0.01807 就补一档，不用等涨够 Δ"，两条
**任一满足即补（或）**。减仓 / 清仓条件一字不动，而且绝对线**只负责触发、不推进
`ref_score`** —— 由它促成的补仓不会顺带把减仓的基准抬高。

先分清数值撞车：`strong_score` 本来就 = P97 = 0.01807，但它管的是**建仓**给多厚
（分数在 [建仓线, 强线] 之间线性插值到 `max_entry_weight` 8%）；本节的线管的是
**已持仓要不要再加一档**，旋钮是 `add_score_line`。两条规则数值相同纯属同一把尺子。

1. **方向与"再设一道门槛"的直觉相反：这条线比 Δ 更松。** 能触发首次补仓的最低分数
   （走 Δ 那条腿）= 建仓线 0.01354 + Δ 下限 0.005 = **0.01854 = P97.17**，比
   P97 = 0.01807 **高** 0.00047。所以在候选池上，"涨够一档"只有 **2.6%** 的名字-轮成立，
   而"够到 P97"有 **7.7%**，并集仍是 7.7% —— 其中 **5.0%（= 全部候选的 2/3）只能靠这条
   水平线放行**（44 对相邻月末、2,461 个"过建仓线名字-轮"观测，`logs/add_line.log` §1b）。
   ⚠ 实现的第一版把这条线当成了"**且**"（必须先涨够一档、还须在 P97 上方），那时它是恒真
   条件、一个数都不会改；按"或"改完才真的开始咬。旋钮名字也从 `add_score_gate` 改成
   `add_score_line`。

`config.yaml` 现取 0.01807 = P97），行为由 `tests/test_position_policy.py` 里 9 项测试钉住（关闭时与旧行为逐股
一致、水平线可在没涨够一档时补仓、**不推进减仓基准**、每轮重复触发直到 16% 上限、两条
同时成立时按 Δ 计档数、不高于建仓线的取值直接报错、`config.yaml` 里这条键确实喂进了
策略对象）。

## 9. 什么时候它会亏钱

三种情形，都会在现场看到：

1. **模型漂移**。要分清两种漂移，现场看到的是**第二种**：
   - *分数级别下移*（整池子一起掉线）→ 一次性清仓、留大量现金空等。这条在现行样本里没真
     发生过，而且**清仓线抬到 P84 之后更难发生**：逐月"分数低于清仓线"的占比在
     **65.2%~96.0%、均值 83.8%**（最松的月份是 2024-02，也只判死 65%，从不全军覆没），
     2026 年各月是 68.9%~93.9%。至于"分数转负"，那是**旧线 0** 的语义（0 = P32.92），
     现行档早就把它换成了"掉出最前 16% 就走"。出处 `research/monthly_scores.py` →
     `logs/monthly_scores.log`（实测 1 秒）。
   - *排序能力归零* → 分数照样给，但"分高 = 后来涨"这件事不再成立。2026 年日均 RankIC
     **−0.0001**（2023/24/25 是 +0.0181/+0.0194/+0.0260，`docs/model-LightGBM.md` 分年那一行）。
     这种漂移 `sell_score` 抓不到（它只看个体分数，不看预测准不准），抓它的是暴露层的
     60 日已兑现 RankIC 门控：2026-05~09 连续触发 5 次、上限乘 0.5 压到全期最低 14%。
     但**别把它当成已经买到手的保护**：2026 这一年 A+B +33.2% 对只开 B +24.8%，差 8.4pp，
     而 8.4pp 恰好压在"只免一项费率"那条 9.87pp 同族带里（严格说两档是不同暴露层，连这条带
     都不适用），并且门控的全样本净效果是负的（只开 A 比纯带位少 50.22pp，§8 第 3 条）。
     它是一道还没被证明有效、但确实唯一针对这种漂移的闸。
2. **个股崩跌**。600002 从 20 元跌到 14 元、期间反弹到 17 元那一幕：反弹把分数抬回
   补仓线以上 → 补仓 → 继续跌破 14 元 → 触发清仓线，一次崩盘里**买高卖低各一次**。
   规则不区分"跌是因为崩盘还是因为噪音"，只按分数动。**现行清仓线（P84）让这条路走得更短**：
   直接清仓从 82 次变 **125** 次、减仓从 29 次变 13 次（§8-C 的现行档实测），也就是"先削一点"几乎不再发生，
   一次崩盘多半是整只进出。副作用是**减仓价锁几乎不再武装**：它是减仓成交时才记下的价格
   天花板，45 轮里只剩"到期自动解除 8 次、真正拦住重建 0 次"（`research/action_notes.py` →
   `logs/action_notes.log`，旧档写的 55 / 1 是清仓线还在 0 时的数）。
3. **全市场同跌**。所有持仓同时靠一个模型的分数判生死，个股之间没有分散保护，只剩
   月度频率、目标波动、IC 门控三道闸。**这就是 §8-A 那层暴露约束存在的唯一理由。**


## 10. 想改规则，改哪个旋钮

- **觉得太激进** → 先别动分数线（那只改变换手），去调暴露层的**目标波动**（`exposure_overlay.vol_target_ann`，10%→8%：现行默认档实测 Sharpe 1.87→**2.03**、回撤 19.95%→**12.93%**、累计 −9.98pp，见 §B）。
- **觉得踏空** → 看的是 `exposure_overlay` 那一层，不是 `buy_score`。
- **嫌"拿太久 / 撤太慢"** → 那才是 `sell_score`（现行 P84）。但先看 §8-C：在现行默认档上它买到的是
  累计（+12.68pp，勉强出 9.87pp 同族带），回撤那一列**反而变差 0.69pp**；再往上抬一档 P90 就
  净亏 28.85pp、回撤多 7.30pp；而且**同一处改动换一层暴露层，符号会翻**（只开 A 那档是 −8.45pp）。
- **嫌手续费高** → 调大 `step_score_floor`（补/减仓门槛更严）或调高 `min_trade_value`。
- **嫌太集中** → 调 `max_position_weight`（16%）或 `add_step_weight`。
- **嫌"涨上去了却没加仓"** → 这条**已经开着**：`add_score_line: 0.01807` = P97（2026-09-27 采纳）。
  "或"关系下它是**放宽**：走 Δ 那条腿要 0.01854 才够，很多名字一辈子够不到。现行档实测 +38.83pp、
  Sharpe 1.663→1.873、补仓 1→12 笔（其中 10 笔只靠这条线，逐笔当日全额成交，§8-E 第 5 条给了
  分数明细）。但要知道两件事：**(1) 五层暴露里有两层翻负**（静态 30%/4 只那档 −65.97pp）、
  五层回撤一致变差（+0.91 ~ +6.72pp）；**(2) 它是带条件的采纳** —— 名额一收到 4~7、或总仓位一压到
  30%~45%，就要把这行改回 `0.0`（§8-E 第 10 条）。想再往上调到 P99 = 0.02888：相对关着只多
  10.11pp（+172.20%）、比现行 P97 少 28.72pp、补仓 12→6 笔，不划算。
  另一条路是调小 `step_score_floor`（0.005）
  或 `step_multiplier`（1.0），但 Δ 是**补、减共用**的，减仓门槛会跟着一起松
  （§8-E 第 7 点用 D 档量过这件事的价钱）—— 未单独测。
- **嫌只数太少** → 把 `base_weight` 调小，能塞进总上限的只数上限
  `⌊(max_total_pct − add_reserve_weight)/(base_weight×(1+费率))⌋` 会跟着变大，但
  `max_names` 本身不会自动变，要一起改；`add_reserve_weight` 也必须跟着调，否则没有
  补仓额度，"涨上去不加仓"就回来了。
- **改了分数线** → 重跑 `python research/calib_stats.py`（分位、每日过线只数、过线成色、
  顶端集中度一次出）确认目标档没被只数上限卡住（现行买线上方日均 57 只，896 个交易日里
  只有 1.6% 的日子凑不满 12 个名额，分数线其实不生效），以及
  `python research/no_lookahead.py` 确认没有把前视带进来。
- **改了暴露层任何一条** → 重跑 `python research/h5_arms.py`（三档 + A/B 归因 + 静态对照
  + 目标波动扫描，全套实测 44 秒，不用重训）。

## 附录 B：几个容易搞错的术语

| 术语 | 它到底是什么 | 容易当成什么 |
|---|---|---|
| **仓位上限**（暴露层输出） | 这一轮最多能用掉多少比例的资金（0~1） | 以为它是"止损线"——它不是，它是预算 |
| **RankIC 门控** | 过去 60 个交易日里已经兑现的那批"预测 vs 后来实际涨跌"的排名相关性均值 | 以为是"模型预测得好不好"的实时打分——它滞后 5 天，且已经打完全算 |
| **已实现波动** | 全池 1000 只股票等权日收益的年化标准差，只取 20 日 | 以为是组合自身的波动——组合自己的波动受仓位影响，是结果不是输入 |
| **`scale`** | 上限乘数（0.3~1.0），"只降不升"意味着市场平静时不加杠杆 | 以为是仓位比例 |
| **`gated`** | IC 门控这一轮是不是生效 | 以为只降上限——它还同时禁止开新仓（`entry_allowed = False`） |
| **基线** `max_total_pct` = 95% | 暴露层没启用时的硬顶，乘数是在它之上再乘 | 以为是"仓位 = 95%" |
| **`max_steps_per_eval` = 2** | 一次评估最多补/减 2 档 | 以为是每天动作上限，它是**每次**评估 |
| **`min_trade_value` = 10000** | 补/减仓这一笔的名义额下限；**清仓不受此限** | 以为小仓位就关不掉 |
| **减仓价禁令** | 减过仓的股票，60 天内补仓的参考价不能高于实际减仓价 | 以为是"跌了就不许再买"——它是把"卖便宜了"这件事记在账上。**现行档它几乎不武装**：只有 `trim` 成交才记账，而清仓线抬到 P84 后 trim 只剩 13 次，45 轮里到期解除 8 次、真正拦住重建 **0** 次（`logs/action_notes.log`） |
| **`de_gross`** | 暴露层把本轮上限压到低于现有仓位时，按权重**等比卖出**到上限（风险动作：不推进分数状态、不设减仓价） | 以为是"补仓"，也以为它等于按分数减仓 —— 现行档 45 轮里它发生 10 次 |
| **`exit_by_trim`** | 本来只是要减仓，结果减到低于 `min_hold_weight` 变成清仓 | 以为是触发清仓线走的（现行档 6 次，另有 125 次是真按清仓线清的） |
| **`add`（补仓）** | 分数比"上一次动作的参考分数"再涨够一个 Δ、**或**够到 `add_score_line`（现取 P97 = 0.01807）才做的那一档 | 以为是常态动作 —— 只按 Δ 那条腿时 45 轮里它只发生 **1 次**（同期 141 笔建仓），把补仓全禁掉净值只动 −0.44pp（9.87pp 同族带内，§8-E 的 E 档）；2026-09-27 起多了一条"或"到 P97 的腿，它才变成 **12 次**（§8-E） |
| **欠配（`underalloc`）** | 目标买不满，因为总仓位上限本来就低（只数上限、给补仓留的额度） | 以为策略没选出来——它选出来了，只是没买足；**不是撮合失败**：现行档 45 次评估里买入只被开盘涨停挡过 1 笔 |
| **`h`（标签周期）** | 模型预测的是未来第 5 天的收益，门控也只数已走完 5 天的观测 | 以为窗口和标签是同一个数（60 是窗口，5 是标签） |
| **平均仓位 / 只数** | 36.1% / 4.0 只（45 次评估的平均目标仓位与平均持仓只数） | 以为 12 只用满——12 是上限，实际平均只有 4.0 只 |
| **交易成本占比** | 5.92% 的初始本金（298 笔，费后），不是占收益的比例 | 以为是手续费占收益的百分比 |
