# QuantLab — A股量化研究与回测框架

> 面向初学者的完整量化研究框架：数据 → 因子 → 模型 → 回测 → 模拟盘

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 一键运行全流程
python main.py pipeline --universe 000852 --start 2021-01-01 --end 2025-12-31

# 3. 或分步执行
python main.py download --universe 000852 --start 2021-01-01 --end 2025-12-31
python main.py factors --start 2021-01-01 --end 2025-12-31
python main.py train                      # Walk-Forward 滚动训练（可用 --min-train-months/--retrain-months 覆盖）
python main.py backtest --capital 1000000
```

## 核心设计

| 模块 | 关键特性 |
|------|---------|
| **数据** | 腾讯行情直连（前复权）+ akshare/东财两级降级，Parquet本地缓存，8线程并发 |
| **因子** | ~28个技术因子，缩尾→标准化→滞后防未来函数；基本面默认关闭（实时快照映射历史=未来函数） |
| **模型** | LightGBM 回归预测**未来 5 日**收益率，Walk-Forward 滚动训练（每 6 个月重训，全样本外预测） |
| **回测** | 事件循环引擎，含佣金/印花税/滑点，月度调仓，涨停不买/跌停不卖/停牌不成交，缺行按最近收盘估值，支持基准指数超额对比 |
| **模拟盘** | T+1规则，100股整手，涨跌停不可交易（板块 10%/20%，与回测共用 `utils/market_rules.py`） |

## 数据获取（`data/downloader.py`，2026-09-22 重写）

旧路径是 akshare 的 `stock_zh_a_hist_tx`：它按**自然年**一年一个 HTTP 请求，
复用不了连接，仓库里还额外对每只股票 `sleep(0.5+随机)` 串行跑 —— 1000 只约
75 分钟。新路径直连腾讯 `newfqkline`，一次 640 根、按 `end` 向前翻页，
线程池并发 + 全局令牌桶限速：

| | 旧 | 新 |
|---|---|---|
| 1000 只全量 | ≈75 min | **2.3 min**（8 线程 / 20 请求每秒，7.3 只每秒） |
| 12 只 A/B | 24.8 s | **0.7 s**（34.7×） |
| 缓存已覆盖 | 仍发请求 | 0 请求，直接切片 |

其余口径：

- **三级降级**：直连腾讯 → akshare 腾讯 → 东方财富。任一级失败才进下一级，
  每次失败把令牌桶速率减半（有地板），恢复时 ×1.5 不冲过设定值。
- **列与单位**（三条路径写进缓存后完全一致）：`成交量`=股、`成交额`=元、
  `换手率`=小数。两处是实测出来的坑：akshare 把 `sz000` 当指数漏乘 100，
  而 `sz000` 同时命中平安银行/万科这类深市主板股票（实测成交量×价格 vs 成交额
  差 100 倍）；东财 `stock_zh_a_hist` 的成交量是手。修正只动绝对值——项目里
  成交量只用于量比（与自身均量之比）和停牌判定（是否为 0），尺度无关，
  因此不改任何已发布数字。
- **等价性**：7 只股票（含科创板 / 001 号段 / 长历史）与 akshare 逐字段比对，
  maxdiff 全为 0；`tests/test_downloader.py` 24 项离线测试钉住翻页语义、
  单位换算、缓存增量与降级链。
- **基准指数**：`download_index_daily("000852")` 走同一条直连通道（东财指数接口
  在本机 IP 上常年 `RemoteDisconnected`）。指数前缀规则与个股不同，
  000 号段在上海，故单独走 `index_symbol()`，不能让 `tx_symbol()` 把它判成深市股票。

## 分数带位仓位管理（`position_policy`，2026-09-22 起默认开启）

Top-K 等权 50 只的问题：权重与分数无关，第 50 名和第 1 名同仓，月末一次性换手
把全部筹码暴露在同一天的模型误差上。`config.yaml` 的 `position_policy.enabled`
打开后，"该买谁"不再是名单，而是**分数带 + 每只股票自己的建仓基准**的函数
（状态机在 `utils/position_policy.py`，与 quantlab2 同一份实现）：

| 规则 | 常量 | 语义 |
|------|------|------|
| 建仓线 / 清仓线 | `buy_score` / `sell_score` | 分数 ≥ 建仓线才入场；跌破清仓线整只清空 |
| 基准仓 | `base_weight` = 5% | 每笔建仓的绝对市值占比（`normalize=False`，归一化会让"5%"失去含义） |
| 建仓上限 | `max_entry_weight` = 8% | 分数越高首笔越大，到 `strong_score` 给满，封顶 8% |
| 补仓触发 | Δ = `step_multiplier` × (建仓分数 − 建仓线) | 比 `ref_score` 再涨够一个 Δ 才补一档，Δ 冻结在该股状态里 |
| 持仓上限 | `max_position_weight` = 16% | 每档 `add_step_weight`，到 16% 锁死 |
| 减仓 | 带内回落 | 分数下降但未破清仓线 → 每档 `trim_step_weight`，减到低于 `min_hold_weight` 改清仓 |
| 回补禁令 | `trim_price` | 记实际减仓成交价，此后补仓参考价不得高于它（`trim_price_ttl_days` 自然日内有效） |
| 最小笔额 | `min_trade_value` = 10000 | 不足一万不下单，下一轮分数继续走再试 |

链路分工（**只有这三条**实现策略，其余调仓入口在策略打开时会明确报错/告警，
不会静默按等权摊派下单）：

- `python main.py backtest` — `backtest/engine.py` 逐评估日跑同一个状态机，
  摘要里多出"策略动作 / 平均目标仓位 / 平均持仓只数"三行诊断。
- `python live/run_daily.py [--simulate|--qmt]` — 策略模式下**每个交易日**评估
  （月末才看一次会把月内的补/减档全丢掉），每只股票的状态存
  `live/state/policy_state.json`，只在**实际股数发生变化**后推进；涨跌停、停牌、
  资金不足挡下的单子下一轮自动重做。
- `python main.py paper-trade` — 走同一条状态机，但节奏仍是月末（函数按
  `rebalance_dates` 循环），启动时会打警告：看策略表现请用 `backtest`。

⚠ 阈值量纲取决于 `model.type` 与 `model.horizon`：`regressor` 的分数是预测
`horizon` 日收益率（现行 `horizon: 5`，`buy_score: 0.0089` = 预期 +0.89%），
`classifier` 的分数是上涨概率（0~1），默认阈值在分类头下等于不建仓。**改
`model.horizon` 会整体缩放分数分布**（同一分位点：5 日 P84=0.0089，20 日 P84=0.030），
阈值必须按同一分位数重推——旧值直接搬过去等于人人都过建仓线。改动任何带位参数都会让
既有回测结论作废，需要重跑回测（`predictions.parquet` 本身不变，**不需要重训**）。

## 组合级暴露层（`exposure_overlay`，2026-09-22 起默认开启）

带位状态机只管"单票给多少、名额几个"，`max_total_pct` 是一个写死的数。上面
那张表说明写死的数才是回撤的开关，于是把它变成每轮按市场状态现算的量
（`utils/exposure.py`，与 quantlab2 同一份实现）。两条通道乘在同一个系数上：

| 通道 | 算式 | 打的是哪一段 |
|------|------|------|
| **B 目标波动** | `scale = clip(vol_target_ann / 近 20 日全池等权已实现年化波动, 0.30, 1)`，只降不升 | 高波动段照常满仓 → 波动尖峰期风险翻倍 |
| **A 运行时 IC 门控** | 近 60 日**已兑现**（标签走满 `ic_horizon_days`=5 日）截面 RankIC 均值 < 0 → 上限再 ×0.50，且新仓与补仓全部挂起 | 模型失效还满仓 |

系数落在哪：`policy_plan(..., max_total_pct_override=上限×scale,
entry_allowed=不触发门控)`，override 只能压低基线（`min()` 兜住），清仓出口
永不受限。三条链路（`main.py backtest` / `live/run_daily.py` /
`main.py paper-trade`）都经 `overlay_args()` 这一个翻译点取参数，回测与实盘
不会各算各的。**无前视**：两个量只用信号日收盘及之前的信息，成交在次日开盘；
`at()` 只取观测日 ≤ 评估日 − `ic_horizon_days`（现行 5）个交易日的 RankIC 片段，
`tests/test_exposure.py`
里用"截断历史重算必须逐点相等"钉住这条。波动用全池等权而非组合净值，是因为
开局没有净值历史，而多头组合的波动几乎就是它的波动（β≈1.11、ρ≈0.92）。

| **A+B：IC 门控 60 日 + 目标波动 10%（当时的默认档）** | **+121.6%** | **1.22** | **23.21%** | 301 | 4.29% | 36% / 5.8 |
| 只开 A：IC 门控 60 日 | +180.9% | 1.10 | 41.12% | 557 | 8.74% | 70% / 11.0 |
| 只开 B：目标波动 10% | +88.9% | 0.93 | 23.21% | 319 | 4.48% | 40% / 6.4 |
| A+B：目标波动 15% | +113.5% | 0.94 | 39.05% | 409 | 5.26% | 51% / 8.6 |
| 对照：静态上限 45%（名额 7 只） | +99.0% | 1.09 | 24.26% | 263 | 3.89% | 38% / 6.1 |
| 对照：静态上限 30%（名额 4 只） | +98.9% | 1.39 | 21.69% | 172 | 2.61% | 25% / 3.6 |

前 12 行是 `position_policy` 的档位（无暴露层），后 6 行是 `exposure_overlay`
的同口径 A/B（`policy_grid.py` §5，44 个月度评估）。

四条结论，改代码之前先看清：

1. **分数线不控制暴露**。每日过线只数：`0.01` 均 449、`0.02` 均 280、`0.03` 均 148
   （最差一天仍剩 11 只）、`0.05` 均 29（2024、2025 各有一天挂 0）。只有抬到 0.05 才偶尔
   真的挡在 `max_names=12` 前面，可那一档回撤 42.69%，比 0.01 档的 36.34% 更差 ——
   "没有新名字可买"不等于"把手上的卖掉"，`sell_score` 还挂在 0。把线从 0.01 抬到 0.05
   只让平均仓位 83%→70%。想压回撤只有两条路：压总仓位（上限 60% →
   33.1%）或加组合级门控（MA200 → 19.2%，代价是收益 +123%→+29%；MA100 在样本里
   翻转 20 次，把收益磨成 +11.8%）。压总仓位这一条现在做成了代码里的
   `exposure_overlay`（见上一节），趋势门控仍然只有 MA200 这种硬开关、未接入。
   （h5 现行档同一算法：买线 0.0089 日均 147 只过线，12 个名额先于分数线用满 ——
   这条机制与标签长度无关。）
2. **收益的提升来自集中，不来自择时**。Top-12 相对 Top-50 的月度收益差只有
   +0.24%/20 日，44 个月里 **18 个月**为正（区间 −3.13% ~ +12.32%）；2023 年 top 1.2%
   是全部分桶里**最差**的（−1.87%，而 5–10% 桶只有 −0.14%）。+123% 里 2024 一年占
   +75.2%，分年是 2023 −12.7% / 2024 +75.2% / 2025 +18.1% / 2026 +26.9%（h20 档）。
   h5 现行档同一检验：分数前 12 只随后 20 日的超额均值 +1.40%/月（h20 档 +0.73%），
   但月度中位仍是 −1.30%、44 个月里只有 19 个月为正 —— 头部变厚了，"靠集中不靠择时"
   这条没变；分年 2023 +3.5% / 2024 +56.7% / 2025 +20.1% / 2026 +22.0%，不再由单独
   一年扛起全部收益。
3. **评估频率要贴着标签**（只在 h20 上实测过）。周度评估把 Sharpe 打到 0.04（565 笔
   →1271 笔，成本 12.3%）：20 日收益率的分数一周内基本没动，多看几次只是多付一次
   换手。**换成 5 日标签后月内节奏没有重测**，现行仍是月度评估 —— 分数现在动得更快，
   月度是"够了"还是"太慢"是个还没回答的问题。
4. **暴露层有效，但增益的来源要摊开说**。h5 现行档（A 门控 60 日 + B 目标波动 10%）
   相对"只开带位"：Sharpe 0.77→**1.53**、回撤 44.50%→**18.95%**、成本 7.48%→4.39%，
   累计 +112.8%→**+137.8%**，代价是平均仓位 74.3%→35.0%、持仓 11.6→5.3 只
   （`add_reserve_weight` 的 5% 预留 + 名额被上限压到 7 只）。h20 那一版的对应结论是
   "累计几乎不变（+123.2%→+121.6%）、只有风险变好"，换到 5 日标签后连绝对收益都一起
   变好了。三点保留：
   (a) 5 日标签下 A 触发 8 次，分布在 2023-05、2024-01~02、2026-05~09 三段，不像 h20
   那样全挤在样本最后 13 个月（那 13 个月正是模型失效段，只开 A 的 +180.9% 全部来自
   这里），但 8 次里仍有 5 次落在最近 5 个月，样本内挑选的嫌疑没消干净；
   (b) 静态上限 45% 单跑（h20）就有 Sharpe 1.09 / 回撤 24.3%，B 相对"直接少下注"的
   增量只有 +0.13 —— 这一对照档在 h5 上还没重跑，所以"B 到底买到了什么"仍未结案，
   留它的理由是对波动状态自适应（全池波动降到 12% 时自动放开到 79% 上限，静态档不会）；
   (c) 静态上限 30% / 4 只那一档（h20）Sharpe 1.39 更高 —— 它说明继续往下压仓位还在
   改善风险调整收益，但也意味着"回撤主要由暴露决定"这条结论还没找到底。


## 回测有没有用未来数据（2026-09-25 审计）

判据只有一条：**把某个切点之后的数据毁掉，切点之前的一切必须逐格不变**。切点取
2025-06-30，可复现脚本 `_no_lookahead.py`（末行是记账对账，不是前视探针）。

| 环节 | 扰动 | 结果 |
|---|---|---|
| 撮合与盯市 | 切点之后的价格 ×0.5 / 整段砍掉，各跑一遍全量回测 | 切点之前 887 天净值最大差 **0.00e+00 元**、成交流水差 **0 笔**；期末净值分别掉到 1.945× / 1.744×（扰动确实生效） |
| 技术因子 | 只用切点之前的 K 线重算，与全样本值逐格比对 | 抽样 60 只（切点前 ≥120 根）× 1,616,160 单元格，**不一致 0 格** |
| walk-forward 标签 | 数落在训练窗口边界重叠区里的月度信号日 | horizon=5：**0/44** 个信号日落进重叠区（horizon=20 是 8 个）—— 短标签顺带消掉了这类边界污染 |
| 按笔盈亏口径 | Σ每笔已实现盈亏 vs 净值变动 | +1,404,987 元 vs +1,406,798 元，倒挤出的浮动盈亏只有 +1,811 元（期末持仓市值 56,526 元）；旧口径"卖额−卖出费"给的是 14,715,237 元 = 10.5× 净值变动，那是现金流不是盈亏 |

结构上防前视的四处，读代码时值得先看：因子一律 lag 1 期、处理只按 `groupby("date")`
做截面运算；`close.shift(-h)/close` 这个标签只进训练目标，绝不进特征；信号日收盘决定
→ 次日开盘成交（涨停不买、跌停不卖、停牌不成交）；暴露层只取"观测日 ≤ 评估日 − h"
的已兑现 RankIC。基本面默认关闭（`use_spot_data: false`）也是同一条理由——实时快照
平铺到历史日期就是未来函数。

一处不影响前视但值得知道的粗糙：`factor_panel` 的行序并不按日期单调，所以 `cmd_train`
里"取训练集尾部 15% 做 early stopping"那一刀切到的不是时间上最后的 15%。未来的数据
仍然进不去（`date < 窗口起点` 的过滤在切片之前），但早停用的验证片段是散布在各期的。
