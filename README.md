# QuantLab — A股量化研究与回测框架

> 面向初学者的完整量化研究框架：数据 → 因子 → 模型 → 回测 → 模拟盘
>
> 第一次接手先读 `docs/入门.md`；只想看清"这个工作区有什么、从哪进"，看上一级的 `../总览.md`。

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 一键运行全流程（日期不写 = 2021-01-01 到今天；本机因子面板现为 2021-01-04~2026-09-22）
python main.py pipeline --universe 000852 --start 2021-01-01 --end 2026-09-22

# 3. 或分步执行
python main.py download --universe 000852 --start 2021-01-01 --end 2026-09-22
python main.py factors --start 2021-01-01 --end 2026-09-22
python main.py train                      # Walk-Forward 滚动训练（可用 --min-train-months/--retrain-months 覆盖）
python main.py backtest --capital 1000000
```

## 核心设计

| 模块 | 关键特性 |
|------|---------|
| **数据** | 腾讯行情直连（前复权）+ akshare/东财两级降级，Parquet本地缓存，8线程并发 |
| **因子** | 25 个技术因子（`factor_panel` 实测列数），缩尾→标准化→滞后防未来函数；基本面默认关闭（实时快照映射历史=未来函数） |
| **模型** | LightGBM 回归预测**未来 5 日**收益率，Walk-Forward 滚动训练（每 6 个月重训，全样本外预测） |
| **回测** | 事件循环引擎，含佣金/印花税/滑点，月度调仓，涨停不买/跌停不卖（按**次日开盘涨跌幅**判，撮合价就是开盘价）/停牌不成交，缺行按最近收盘估值，支持基准指数超额对比 |
| **模拟盘** | T+1规则，100股整手，涨跌停不可交易（板块 10%/20%，与回测共用 `utils/market_rules.py`） |

## 数据获取（`data/downloader.py`，2026-09-22 重写）

旧路径是 akshare 的 `stock_zh_a_hist_tx`：它按**自然年**一年一个 HTTP 请求，
复用不了连接，仓库里还额外对每只股票 `sleep(0.5+随机)` 串行跑 —— 1000 只约
75 分钟。新路径直连腾讯 `newfqkline`，一次 640 根、按 `end` 向前翻页，
线程池并发 + 全局令牌桶限速：

| | 旧 | 新 |
|---|---|---|
| 1000 只全量 | ≈75 min | **2.3 min**（8 线程 / 20 请求每秒，7.3 只每秒） |
| 12 只 A/B | 24.8 s | **0.7 s**（34.7×） |
| 缓存已覆盖 | 仍发请求 | 0 请求，直接切片 |

其余口径：

- **三级降级**：直连腾讯 → akshare 腾讯 → 东方财富。任一级失败才进下一级，
  每次失败把令牌桶速率减半（有地板），恢复时 ×1.5 不冲过设定值。
- **列与单位**（三条路径写进缓存后完全一致）：`成交量`=股、`成交额`=元、
  `换手率`=小数。两处是实测出来的坑：akshare 把 `sz000` 当指数漏乘 100，
  而 `sz000` 同时命中平安银行/万科这类深市主板股票（实测成交量×价格 vs 成交额
  差 100 倍）；东财 `stock_zh_a_hist` 的成交量是手。修正只动绝对值——项目里
  成交量只用于量比（与自身均量之比）和停牌判定（是否为 0），尺度无关，
  因此不改任何已发布数字。
- **等价性**：7 只股票（含科创板 / 001 号段 / 长历史）与 akshare 逐字段比对，
  maxdiff 全为 0；`tests/test_downloader.py` 24 项离线测试钉住翻页语义、
  单位换算、缓存增量与降级链。
- **基准指数**：`download_index_daily("000852")` 走同一条直连通道（东财指数接口
  在本机 IP 上常年 `RemoteDisconnected`）。指数前缀规则与个股不同，
  000 号段在上海，故单独走 `index_symbol()`，不能让 `tx_symbol()` 把它判成深市股票。

## 分数带位仓位管理（`position_policy`，2026-09-22 起默认开启）

Top-K 等权 50 只的问题：权重与分数无关，第 50 名和第 1 名同仓，月末一次性换手
把全部筹码暴露在同一天的模型误差上。`config.yaml` 的 `position_policy.enabled`
打开后，"该买谁"不再是名单，而是**分数带 + 每只股票自己的建仓基准**的函数
（状态机在 `utils/position_policy.py`，与 quantlab2 同一份实现）：

| 规则 | 常量 | 语义 |
|------|------|------|
| 建仓线 / 清仓线 | `buy_score` / `sell_score` | 分数 ≥ 建仓线才入场；跌破清仓线整只清空 |
| 基准仓 | `base_weight` = 5% | 每笔建仓的绝对市值占比（`normalize=False`，归一化会让"5%"失去含义） |
| 建仓上限 | `max_entry_weight` = 8% | 分数越高首笔越大，到 `strong_score` 给满，封顶 8% |
| 补仓触发 | Δ = `step_multiplier` × (建仓分数 − 建仓线) | 比 `ref_score` 再涨够一个 Δ 才补一档，Δ 冻结在该股状态里 |
| 持仓上限 | `max_position_weight` = 16% | 每档 `add_step_weight`，到 16% 锁死 |
| 减仓 | 带内回落 | 分数下降但未破清仓线 → 每档 `trim_step_weight`，减到低于 `min_hold_weight` 改清仓 |
| 回补禁令 | `trim_price` | 记实际减仓成交价，此后补仓参考价不得高于它（`trim_price_ttl_days` 自然日内有效） |
| 最小笔额 | `min_trade_value` = 10000 | 不足一万不下单，下一轮分数继续走再试 |

链路分工（**只有这三条**实现策略，其余调仓入口在策略打开时会明确报错/告警，
不会静默按等权摊派下单）：

- `python main.py backtest` — `backtest/engine.py` 逐评估日跑同一个状态机，
  摘要里多出"策略动作 / 平均目标仓位 / 平均持仓只数"三行诊断。
- `python live/run_daily.py [--simulate|--qmt]` — 策略模式下**每个交易日**评估
  （月末才看一次会把月内的补/减档全丢掉），每只股票的状态存
  `live/state/policy_state.json`，只在**实际股数发生变化**后推进；涨跌停、停牌、
  资金不足挡下的单子下一轮自动重做。
- `python main.py paper-trade` — 走同一条状态机，但节奏仍是月末（函数按
  `rebalance_dates` 循环），启动时会打警告：看策略表现请用 `backtest`。
  ⚠ 而且它的**成交比回测晚约一个月**：`SimulatedBroker` 的待成交单要等下一次
  `process_daily` 才撮合，而这条链每月才调一次 → 实测第一笔 2023-03-01（回测 2023-02-01）、
  全历史重放 **+44.37% / 233 笔 / 胜率 50.0%**（回测同一份分数 +162.09% / 310 笔）。
  这 118pp 是"晚进场"，不是规则分歧 —— 三个方向的成交时点对照见
  `docs/entry-位置管理.md` §7（含 `run_daily.py --simulate` **早一天**的那个反向问题）。

⚠ 阈值量纲取决于 `model.type` 与 `model.horizon`：`regressor` 的分数是预测
`horizon` 日收益率（现行 `horizon: 5`，`buy_score: 0.01354` = 预期 +1.35%），
`classifier` 的分数是上涨概率（0~1），默认阈值在分类头下等于不建仓。**改
`model.horizon` 会整体缩放分数分布**（同一个 P84 分位点：h5 实测 0.00875，`logs/calib_stats.log`
§1；h20 那一版当年落在 0.030 附近、旧缓存已不在故无复核值，两者差约 3.4 倍），阈值必须按同一分位数重推——旧值直接搬过去等于人人都过建仓线。改动任何带位参数都会让
既有回测结论作废，需要重跑回测（`predictions.parquet` 本身不变，**不需要重训**）。

## 组合级暴露层（`exposure_overlay`，2026-09-22 起默认开启）

带位状态机只管"单票给多少、名额几个"，`max_total_pct` 是一个写死的数。上面
那张表说明写死的数才是回撤的开关，于是把它变成每轮按市场状态现算的量
（`utils/exposure.py`，与 quantlab2 同一份实现）。两条通道乘在同一个系数上：

| 通道 | 算式 | 打的是哪一段 |
|------|------|------|
| **B 目标波动** | `scale = clip(vol_target_ann / 近 20 日全池等权已实现年化波动, 0.30, 1)`，只降不升 | 高波动段照常满仓 → 波动尖峰期风险翻倍 |
| **A 运行时 IC 门控** | 近 60 日**已兑现**（标签走满 `ic_horizon_days`=5 日）截面 RankIC 均值 < 0 → 上限再 ×0.50，且新仓与补仓全部挂起 | 模型失效还满仓 |

系数落在哪：`policy_plan(..., max_total_pct_override=上限×scale,
entry_allowed=不触发门控)`，override 只能压低基线（`min()` 兜住），清仓出口
永不受限。三条链路（`main.py backtest` / `live/run_daily.py` /
`main.py paper-trade`）都经 `overlay_args()` 这一个翻译点取参数，回测与实盘
不会各算各的。**无前视**：两个量只用信号日收盘及之前的信息，成交在次日开盘；
`at()` 只取观测日 ≤ 评估日 − `ic_horizon_days`（现行 5）个交易日的 RankIC 片段，
`tests/test_exposure.py`
里用"截断历史重算必须逐点相等"钉住这条。波动用全池等权而非组合净值，是因为
开局没有净值历史，而多头组合的波动几乎就是它的波动（β≈1.11、ρ≈0.92）。

**A 通道现行样本里的账是负的**（`logs/h5_arms_p94.log` 的归因档，见下面结论 4(b)）：
只开 B +182.67%，A+B +162.09%，只开 A +77.37% —— A 单独开着连"什么都不加"都不如。
它留在默认档是防御性的（赌"信号失效还满仓"这一段将来会出现），不是样本内买到的东西。
一行 `exposure_overlay.ic_window_days: 0` 就能关掉，不需要重训；本轮未改。

四条结论，改代码之前先看清：

1. **分数线不控制暴露**。h20 那张表的每日过线只数：`0.01` 均 449、`0.02` 均 280、
   `0.03` 均 148（最差一天仍剩 11 只）、`0.05` 均 29（2024、2025 各有一天挂 0）。
   只有抬到 0.05 才偶尔
   真的挡在 `max_names=12` 前面，可那一档回撤 42.69%，比 0.01 档的 36.34% 更差 ——
   "没有新名字可买"不等于"把手上的卖掉"，那一版 `sell_score` 还挂在 0（现行档已抬到
   P84=0.00875，见上面清仓线表；这条结论本身仍然成立，它说的是**建仓线**挡不住回撤）。
   把线从 0.01 抬到 0.05
   只让平均仓位 83%→70%。想压回撤只有两条路：压总仓位（上限 60% →
   34.87%）或加组合级门控（MA200 → 19.2%，代价是收益 +123%→+29%；MA100 在样本里
   翻转 20 次，把收益磨成 +11.8%）。压总仓位这一条现在做成了代码里的
   `exposure_overlay`（见上一节），趋势门控仍然只有 MA200 这种硬开关、未接入。
   （h5 现行档同一算法：买线 0.01354（P94）日均 57 只过线，896 个交易日里只有 1.6%
   的日子候选不足 12 只 —— 12 个名额仍然先于分数线用满，这条机制与标签长度、
   与线抬到哪一档都无关。）
2. **收益的提升来自集中，不来自择时**。现行口径的月度检验（`logs/calib_stats.log` §5：
   每个月末信号日取分数前 N 只等权，减当日全池等权，看随后 20 个交易日）——前 12 只
   超额**月均 +1.36%、中位 −1.58%**，43 个可算的月份里只有 **18 个月**为正，t 值 **+0.80**
   （远不到 2），累计 Σ +58.3% 里最好 3 个月占 **156%**，剔掉那三个月月均变 **−0.82%**。
   往前看前 3 只 +7.12%（为正 22/43、t=+1.30），往后看前 30 只 +0.04%、前 100 只 +0.42%：
   出了前 12 名就全平，后三个数彼此差不到半个点，而这类月度序列单月就能摆几个点
   （前 12 只那列：月度标准差 **11.11%**、中位 −1.58%、最好 3 个月占掉 156%）。5 日窗口
   同一张表，前 12 只月均 +0.47%、为正 22/45。按每日名次给全体 896 天分桶也是同一个形状
   （上面那张分桶表，`research/h5_dist.py`）：top 1.2% 五日 +0.65%，5–10% +0.44%，
   50–100% +0.35%。
   组合层面的贡献同样偏：现行档分年 2023 +6.1% / 2024 +57.9% / 2025 +25.6% / 2026 +24.5%
   （`reports/verify_results.txt`，指数同期 −13.5% / +1.2% / +27.5% / +2.2%；口径 = 年内日收益
   复利，报告自检那行"逐年复利 = 全期累计"给的都是 +162.09%）——
   单年最高 2024 占 +57.9%，其余三年在 +6%~+26% 之间，只有 2025 跑输指数（差 1.9 个点，
   跑输等权组合 15.9 个点）。
   h20 那一版的对应检验（Top-12 减 Top-50 月差 +0.24%、44 个月里 18 个月为正）方向一致，
   只是头部更薄。
3. **评估频率要贴着标签**（只在 h20 上实测过）。周度评估把 Sharpe 打到 0.04（565 笔
   →1271 笔，成本 12.3%）：20 日收益率的分数一周内基本没动，多看几次只是多付一次
   换手。**换成 5 日标签后月内节奏没有重测**，现行仍是月度评估 —— 分数现在动得更快，
   月度是"够了"还是"太慢"是个还没回答的问题。
4. **暴露层里真正在做事的是 B，A 单独开着是负贡献**。归因表在上面
   （`research/h5_arms.py` → `logs/h5_arms_p94.log`），四点摊开：
   (a) **A+B 相对"只开带位"**：Sharpe 0.74→**1.66**、回撤 48.58%→**19.04%**、
       成本 13.90%→5.75%，累计 +146.36%→**+162.09%**（**+15.73pp**，出 6.7pp 噪声带），
       代价是平均仓位 88.9%→35.1%、持仓 11.5→4.3 只（B 给的平均上限 44.8%，扣掉
       `add_reserve_weight` 预留的 5% 之后一轮只塞得下 7 只 5% 基础仓）。h20 那一版的
       对应结论是"累计几乎不变（+123.2%→+121.6%）、只有风险变好"，换到 5 日标签后
       绝对收益也变好了；但注意这一版的 +15.73pp 比上一版的 +43.88pp 小得多 —— 分子
       （带位档自己）被清仓线抬上去了 31pp，暴露层的边际贡献就相应缩了。
   (b) **B 单独就够，A 目前是累赘**：只开 B 是 +182.67% / Sharpe 1.63 / 回撤 19.30%，
       比现行 A+B 多 **+20.58pp 累计**，回撤只多 0.26pp、Sharpe 只差 0.03（20.58pp 出
       这一族的 6.7pp 噪声带，0.26pp 与 0.03 在带内，不能读）。只开 A（不缩波动）
       是 +77.37% / 0.50 / 42.24%，**比完全不加暴露层还少 68.99pp**，只换来回撤从
       48.58% 压到 42.24%。A 触发 8 次（2023-05、2024-01~02、2026-05~09），8 次里
       5 次落在最近 5 个月；h20 那一版"只开 A +180.9%"整个来自样本最后 13 个月
       （正是模型失效段），换到 5 日标签这个来源就没了。结论：**A 没有独立价值**，
       留在默认档只为压"信号已失效却还满仓"这一类状态，而这段样本里没真出现过。
       要去掉它是一行配置 `exposure_overlay.ic_window_days: 0`，不需要重训 ——
       本轮**没有**改，等定夺。
   (c) **"B 到底买到了什么"结案，而且这一版结得更干净**：静态上限 45%（平均仓位 36.3%
       vs B 的 38.5%、只数 4.8 vs 4.9、成本 5.14% vs 7.00%）只有 +65.56% / Sharpe 0.71，
       只开 B 比它多 **+117.11pp**、Sharpe +0.92，回撤还**少** 2.88pp —— 上一版这里是
       "B 多 41.7pp 但回撤多 3.10pp"，那一处方向被清仓线改动翻掉了（静态 45% 档自己
       掉了 67.08pp）。B 买的是"上限跟着波动浮动"（样本里 14%~90%），静态档给不了。
       但再往下压有代价：静态 30% + 名额 4 只是 +115.15% / Sharpe 1.46 / 回撤 18.84%，
       仍低于 B（Sharpe 差 0.17、累计差 67.52pp），h20 那一版"30%/4 只 Sharpe 1.39
       反而比 A+B 的 1.22 高"在现行口径下**不成立** —— 可是这一档自身被清仓线抬了
       74.35pp，所以"静态档到底比 B 差多少"这类结论不能跨参数版本引用。
   (d) **B 的水平本身也没扫到底**：现行口径重扫目标波动（上面第二张表），Sharpe 随目标
       下调单调升到 8%（1.80）、回撤 19.04%→15.47%，而 8%~12% 的累计基本平坦。
       10%→8% 是"少 9.05pp 累计换 3.57pp 回撤"的偏好题（上一版的"换一倍回撤"已作废），
       本轮**没改**，等定夺；地板
       `scale_floor=0.30` 在 8% 那一档已经顶住 11/45 个评估日，再往下就不是同一个旋钮
       在起作用了。


## 回测有没有用未来数据（2026-09-25 首审，2026-09-26 换成交判定/建仓线/清仓线后重跑）

判据只有一条：**把某个切点之后的数据毁掉，切点之前的一切必须逐格不变**。切点取
2025-06-30，可复现脚本 `research/no_lookahead.py`（输出 `logs/no_lookahead_p94.log`，
末行是记账对账，不是前视探针）。

| 环节 | 扰动 | 结果 |
|---|---|---|
| 撮合与盯市 | 切点之后的价格 ×0.5 / 整段砍掉，各跑一遍全量回测 | 切点之前 585 天净值最大差 **0.00e+00 元**、成交流水差 **0 笔**（三个臂都是 310/308/197 笔，切点后行为确实变了：期末净值 2.6504× → 2.0467× / 1.8035×，扰动有功率） |
| 技术因子 | 只用切点之前的 K 线重算，与全样本值逐格比对 | 抽样 60 只（切点前 ≥120 根）× 1,616,160 单元格，**不一致 0 格** |
| walk-forward 标签 | 数落在训练窗口边界重叠区里的月度信号日 | horizon=5：**0/44** 个信号日落进重叠区（horizon=20 是 8 个）—— 短标签顺带消掉了这类边界污染 |
| 按笔盈亏口径 | Σ每笔已实现盈亏 vs 净值变动 | +1,650,385 元 vs +1,650,385 元，**倒挤出的浮动盈亏 0 元**（现行档期末空仓，期末市值 0 元，逐分对平）；每笔卖出已实现盈亏中位 **−842 元**、最好 +463,035、最差 −49,862、卖出手续费合计 35,008 元；旧口径"卖额−卖出费"给的是 18,936,871 元 = 11.5× 净值变动，那是现金流不是盈亏 |

结构上防前视的四处，读代码时值得先看：因子一律 lag 1 期、处理只按 `groupby("date")`
做截面运算；`close.shift(-h)/close` 这个标签只进训练目标，绝不进特征；信号日收盘决定
→ 次日开盘成交（涨停不买、跌停不卖、停牌不成交）；暴露层只取"观测日 ≤ 评估日 − h"
的已兑现 RankIC。基本面默认关闭（`use_spot_data: false`）也是同一条理由——实时快照
平铺到历史日期就是未来函数。

一处不影响前视但值得知道的粗糙：`factor_panel` 的行序并不按日期单调，所以 `cmd_train`
里"取训练集尾部 15% 做 early stopping"那一刀切到的不是时间上最后的 15%。未来的数据
仍然进不去（`date < 窗口起点` 的过滤在切片之前），但早停用的验证片段是散布在各期的。

## 交易成本口径（报的都是费后，各项各收多少）

`python main.py backtest` 打的每一个收益数字都已经扣掉佣金、印花税、滑点。逐笔复核
脚本 `research/cost_audit.py`（2026-09-26 在现行档重跑，输出 `logs/cost_audit_p94.log`，
约 1 分钟）：现行默认档 310 笔流水记入 **57,452 元**，与脚本独立重算的**最大逐笔差
0.000000 元** —— 少一项就是"算了没扣"，多一项就是重复计提，两边逐笔对得上才说明钱真的扣掉了。

| 项 | 费率（`config.yaml` 的 `market`） | 方向 | 本档实收 |
|---|---|---|---|
| 佣金 | 万三，单笔最低 5 元 | 双边 | 10,876 元（含 4 笔小卖出撞下限多出的 5.5 元） |
| 印花税 | 万五，**2023-08-28 前万十，按成交日取档** | 仅卖出 | 10,340 元（分档多收 854 元） |
| 滑点 | 千一 | 双边 | 36,236 元（占总摩擦 63%） |
| 合计 | 买入 13.00‱ / 卖出 18.00‱（名义） | — | 57,452 元 = 本金 5.75% |

（三项按名义费率独立算出来是 57,447 元，与引擎记入的 57,452 差 5.5 元 = 佣金下限那 4 笔，
差额本身也是恒等式的一部分；分项由成交额 × 费率现算，`logs/cost_audit_p94.log` 给了
成交额、实收 bp 与触下限笔数。）

- **滑点按成交额计提现金**（引擎记账是 `现金 -= amount + cost`），不是把成交价抬高千一。
  两者代数等价（`cost = 率 × 数量 × 价格`），只在 100 股整手上差别：折成股数是
  中位 0.046 手、最大 0.599 手，**141 笔买入里没有一笔够换一手**，所以两种口径
  逐笔股数相同。
- 买入实收 13.00‱ 与名义一致；卖出 18.45‱ 略高于名义 18.00‱，因为 4 笔小单撞上 5 元
  佣金下限（下限只咬得到 16,667 元以下的单，本档最小卖出单 10,842 元，最小买入单
  68,024 元）。
  **同一原因**，下单前的资金预留必须逐笔算费用：只按费率比例留钱，会放行买不下的
  单子（`utils/sizing.py` 的 `cost_fn`）。
- 印花税分档：跨档前（2023-08-28 之前）卖出 25 笔 / 1,707,742 元，比"整段按现行档"
  多收 **854 元**（总成本 1.5%、本金 0.085%）。不分档是 2026-09-26 之前的一处真错。
  模拟盘/实盘不读这张表 —— 它们只交易"今天"，用现行档。
- 分年成本占初始本金：2023 1.20% / 2024 0.95% / 2025 2.34% / 2026 1.25%。单笔金额
  中位 113,454 元（P10 57,142 / P90 171,173）。千一固定滑点不含冲击成本，在这个量级
  （中位单笔 ≈ 在册池个股日成交额中位 1.46 亿的 0.08%）是偏保守的常数；本金上到千万级
  必须换成随成交量放大的冲击成本模型。

**读任何档位对照之前先记住这条**：费率一改，成交股数就改，成交股数一改，后面整条
净值路径都改。同一套"只免掉一项费率"的探针在现行档测出期末净值跨度 **0.0670 = 6.7pp**
（现行 2.6504/310 笔、免滑点 2.6462/312、免佣金 2.6505/311、免印花税 2.6509/311、
全零 2.7133/312）——省下的钱只有 1.0%~3.6% 本金，净值却能摆出两倍。现行档"费率全零"
累计 168.07%，比费后的 162.09% 高 **5.97pp**，而名义成本合计是 5.75% 本金，两者那
0.22pp 的差也是路径。所以**小于 10pp 的档位差不能读成"更好/更差"**，它只说明这一档
在头几天恰好买到了/没买到。本轮三处改动里：清仓线自己那一步 +2.87pp **在带内、不能读**；
A0→A3（+48.79pp）、等权→带位（+71.15pp）、带位→A+B（+15.73pp）在带之上、能读；
但同一件事摊到六档上摆到 −67pp ~ +74pp（见上面清仓线表末段），所以"能读"也只对
**同一档改动前后各跑一次**那种对比成立。上一版这里的探针是 17.4pp（09-25 档，
笔数 278→286），两档的噪声地板本来就不同。

## 命令参考

```bash
python main.py download      # 下载数据
python main.py factors        # 计算因子 + 评估

python main.py pipeline       # 一键全流程
```

改参数后该重跑到哪一步：仓位规则（`position_policy`/`exposure_overlay`/`backtest`）
只重跑 `backtest`；改 `factors`/`model.horizon` 要重跑 `train`；改 `universe`/日期才
重跑 `download`+`factors`+`train`。
